## Part 2/3

# 系统与编译器进展

### vLLM TT Plugin：用插件边界容纳非 GPU 式执行模型

**重要性：高。** [vLLM 官方技术文章](https://vllm.ai/blog/2026-09-07-vllm-tt-plugin)介绍了 [Tenstorrent 后端仓库](https://github.com/tenstorrent/vllm-tt-plugin)：平台发现、模型注册、worker、调度器和执行桥全部位于 out-of-tree plugin，vLLM 核心无需承载 TT 专用逻辑。它最有学习价值的不是“新增一种硬件”，而是展示了 serving 抽象如何面对与 GPU 不同的约束：整张 mesh 编译为一个 traced program，步骤必须是纯 prefill 或纯 decode，片上采样按 batch 能力自动回退到 host，并用异步 readback 覆盖 steady-state decode。

Galaxy 上的单程序执行无法照搬“一 rank 一进程”的数据并行，插件因此采用单进程 lane-DP：每个 lane 保持独立队列与 KV cache 管理器，由 coordinator 选择全局 step 模式，再合并设备输入。这是一份很好的“硬件语义如何反向塑造 scheduler/runtime”的案例。当前限制也很清楚：尚无 speculative decoding、LoRA 和多机 serving，混合模型的数据并行组合未在硬件上验证，官方文章也没有给出可审计的统一性能表。

**建议投入：立即学习（1～3 小时）。** 先读文章的 “Plugging in, not forking”“Phase-based scheduling”“Single-process lane data parallelism” 三节，再对照仓库中的 `platform.py`、`scheduler.py`、`lane_scheduler.py` 和 `async_decode.py`；没有 Tenstorrent 设备时不必花时间搭环境，重点提炼插件边界、调度不变量和无进展循环的防护逻辑。

# GitHub 高价值项目洞察

### AI-Hypercomputer/accelerator-agents：把 kernel 优化变成可测量的 Agent 闭环

[官方仓库](https://github.com/AI-Hypercomputer/accelerator-agents)已经包含 MaxKernel、JAXBench、MaxCode、文档和 CI，而不是只有论文说明。MaxKernel 面向 TPU/Pallas kernel，把规划、实现、自调试、测试与硬件 profiling 拆成专门 Agent，并提供人工协作、全自动和图搜索三种模式；[论文](https://arxiv.org/abs/2609.04523)在 50 个 JaxBench 任务及真实模型 workload 上与专家实现对比。

项目的真正价值是 harness 设计：性能指标和 compiler/runtime 反馈被放进搜索循环，而不是让模型一次生成代码。风险是目前强依赖 Google Cloud TPU、Gemini 与 Pallas，论文刚发布、外部复现尚少，仓库也没有稳定 release，因此暂不能把作者报告的“匹配专家实现”外推到 CUDA/通用编译优化。

**建议投入：立即学习（1～3 小时）。** 优先阅读 `MaxKernel` 的 agent orchestration 与 benchmark runner，并挑一个 JAXBench kernel 跟踪“生成—编译—正确性测试—profiling—改写”的完整轨迹；若手头没有 TPU，先读代码与实验设计，不建议为跑通全套环境投入半天以上。

## Part 3/3

# 科研进展

### Don't Drop Dropout：用层级随机深度同时换取训练和推理弹性

这篇 ICML 2026 工作重新评估了已淡出主流 LLM recipe 的 layer dropout。作者报告了 2,400 余组实验，规模覆盖 271M～8.2B 参数、最多 160B tokens；通过整 block、per-sequence dropout，前层保护/后层加大概率的分布，以及训练过程中逐步衰减到零的 schedule，在相同训练 FLOPs 下得到更低 loss，或在近似验证损失下节省最高 25% 训练 FLOPs。训练出的“深度弹性”还能用于 early exit、intermediate-layer skipping 和 self-speculative decoding，作者报告最高约 1.5× 推理加速且准确率损失很小。[论文](https://arxiv.org/abs/2609.05275)

**质量：A；证据成熟度：M0。** 优点是实验量大、覆盖训练与部署两端，且已进入 ICML；主要风险是最大模型仍只有 8.2B、实验硬件集中在 Cerebras CS-3，当前页面未给出可直接复现的作者代码，因此跨架构、超大规模和常见 GPU 栈上的收益仍需验证。

学完后可以更系统地理解“训练时随机深度—推理时可变深度—自 speculative decoding”之间的统一关系，并能为自己的训练 recipe 设计 layer-wise dropout/schedule 消融。**建议投入：立即学习（1～3 小时）**，先看方法中的 scaling factor、Increasing Layer Distribution 和 Decreasing Time Schedule，再核对最大规模实验与推理质量退化曲线；复现资产出现前不建议直接改生产训练配方。

### ACE：无需校准数据的 MoE 动态 expert skipping

ACE 用离线计算的全局谱代理与 router-conditioned expert 方向原型共同估计贡献，运行时只有两种估计都判为低贡献时才跳过 expert，并始终保留 top-1。作者在三种 MoE LLM、八个 benchmark 上报告优于静态和动态 baseline；在 Qwen3.6-35B-A3B 的 50% skipping 设置下，相比最强对照降低 WikiText-2 perplexity 7.96%，平均下游准确率提高 4.15 个百分点。[论文](https://arxiv.org/abs/2609.05228)

**质量：B；证据成熟度：M0。** 训练-free、calibration-free 和 checkpoint-preserving 很适合 serving 侧，但目前仍是作者结果，且论文刚发布、未见代码与第三方复现。**建议投入：了解即可（10～20 分钟）**，先记住“双代理一致才跳过”的保守门控思路，等代码、端到端吞吐与真实并发负载数据后再深入。
