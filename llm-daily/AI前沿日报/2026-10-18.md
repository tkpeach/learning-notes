# 今日总览

- **Kimi K3 的服务优化提供了两组值得细读、但口径不同的证据。** vLLM 在 GB300 上通过模型专用 CuTe DSL 解码路径降低延迟，在 MI355X 上通过缓存分片、状态恢复和 MoE 去重提升 Agent 负载吞吐。前者的同配置基线与后者的跨平台曲线不能相加，也不能推出所有硬件与负载的普遍优势。

# 业界进展

### Claude 追溯 NIST 椭圆曲线参数来源：一个可直接重算的研究结果

**质量：A｜重要性：中｜Personal Utility：中｜原始发布：2026-10-16。** Anthropic 的[原始研究与复现代码](https://www.anthropic.com/research/ecdsa-curve-origins)表明，Claude 从公开种子的位模式入手，识别出旧版 C 库的 `lrand48`，再恢复内部状态与时间戳，重现 NIST P-192、P-224、P-256、P-384、P-521 的种子，以及部分 ANSI 曲线与基点。这里最强的证据是公开的生成程序能逐字节再生标准参数，而不只是模型解释了一个历史故事。它也说明 AI 研究助手在“提出生成过程假设—写程序检验—反推状态”这类有确定性验证器的问题上可能有实际价值。

**边界。** 参数来源的解释不等于发现 ECDSA 攻击，也不能证明所有选择过程均已澄清：B-163 的种子、若干基点来源，以及部分合格候选为何被跳过，仍未解决。当前没有改动密码系统配置的理由。**投入建议：了解即可；** 若研究 AI 辅助可验证发现，可从文末短程序重算 P-256，再检查哪些结论是输出匹配、哪些仍是历史推断。

# 系统与编译器进展

### Kimi K3／GB300：专用解码路径把优化收益和正确性边界一起公开

**质量：A｜重要性：高｜Personal Utility：高｜原始发布：2026-10-16，此前漏报。** vLLM 的[技术复盘](https://vllm.ai/blog/2026-10-16-kimi-k3-megakernel)及其链接的实现 PR，针对单个 NVLink 域内 8 或 16 张 GB300、batch 1～64 的 Kimi K3 解码，构建模型专用 CuTe DSL 路径。它按 batch 选择小矩阵或 split-K 投影，把 all-reduce 融入归一化，重排 MoE 专家计算并预取权重；所示单层时间线由约 23 个 kernel、130 微秒降为 13 个、69 微秒。相较现有 vLLM 主路径，新实现以明确的选择开关进入，并保留 prefill、混合 batch 的标准路径回退，避免把单一配置的捷径当成全模型默认行为。

**可比较的收益。** 在 **同为 TP16、DSpark 7 个 draft token、合成平均接受长度 6、batch 1、只计 decode** 的条件下，优化版为 **842 tokens/s**，现有 vLLM 为 **488 tokens/s**，约 **1.73 倍**。没有推测解码时，TP16 batch 1 为 256.4 tokens/s、约 1.88 倍；batch 16～64 的增益为 1.62～1.71 倍。这些是整个 TP 组的吞吐，不能等同于单卡、含 prefill 的服务收益。文章的 AgentX P90 交互速度 1.8 倍使用 **16 张优化版 GB300 对 8 张先前版本 GB300**，硬件数也变了，不能单独归因于 kernel。

**工程质量证据与限制。** 团队同时检查 kernel 数值、长上下文 MRCR、长生成 AIME25、温度采样与结构化输出；曾发现编译器把激活值读取错误地提前到同步等待之前，独立 kernel 小样本测试也未暴露部分长程数值问题。这比单点速度曲线更值得借鉴：选中优化路径的测试必须真的覆盖该路径和生产功能。当前仅验证所列 Blackwell/NVLink 配置，跨代 GPU 与更广负载尚待复跑。**投入建议：深入学习（半天）。** 先读文章的主路径选择、正确性和 batch/上下文扫点，再看实现 PR；复用时把同硬件、同采样、同前缀缓存的端到端对照作为验收线。

### Kimi K3／MI355X：缓存、专家投影和状态恢复决定 Agent 负载的吞吐

**质量：A｜重要性：高｜Personal Utility：高｜原始发布：2026-10-16，此前漏报。** vLLM 的[AMD 实现分析](https://vllm.ai/blog/2026-10-16-kimi-k3-mi355x)将 AgentX 的优势拆成可追踪的系统变化。TP8 原先让每卡保留完整 MLA 历史；DCP8 将历史位置分到 8 卡，对 **142K token** 的示例，每卡 MLA 载荷估计从 **1.96 GB 降到 245 MB**，并以跨卡归并换取容量。CPU offload 继续保存 MLA 历史和 KDA checkpoint，但恢复点必须对齐；否则一个 3,072-token 缓存命中仍可能从 2,048 重新计算。MoE 路径则将重复的 routed 输出投影按输出坐标分片，并复用已有 all-reduce，不再增加一次集体通信。

**证据如何读。** 10 月 9 日的公开 AgentX 曲线，在 **8×MI355X 对 8×B300、P90 每用户 50 tokens/s** 的点上，分别是 **7,567 与 6,083 总 tokens/s/GPU**，MI355X 高 **24.4%**；按该榜单的 $1.50 与 $2.26/GPU·小时拥有成本假设，折算 tokens/美元高 **87.4%**。总 tokens 包含可复用输入与输出，交互指标不含首 token 延迟，美元是成本模型而非可购买报价。各项 kernel 微基准、关闭前缀缓存的 MoE PR 测试，以及后续释放 3.85 GiB/卡的实验，条件与这条公开曲线不同，不能合并为因果分解。作者也报告长上下文 MLA kernel 有明显收益、短上下文未必受益；高并发缓存容量变化需要等容量复测。**投入建议：深入学习（半天）。** 按“历史分片→checkpoint 对齐→专家重复工作→实际缓存命中率”的顺序读文章与 PR；自己的服务应同时测 TTFT、P90 TPOT、输出吞吐、缓存命中和每卡内存。

### Beam／vLLM：权重开放后的服务主路径有了可审计的性能证据

**质量：A｜重要性：高｜Personal Utility：高｜原始发布：2026-10-16，此前漏报。** 昨日已介绍 Beam 的权重、许可和模型能力；新增的[vLLM 首日服务复盘](https://vllm.ai/blog/2026-10-16-reflection-beam)具体解释如何运行它。52 层中 43 层使用 512-token 滑窗、9 层保留全局注意力；FP8 下全局层 KV 约 **18 KiB/token**，满 100 万 token 约 **18 GiB**（分片前）。实现把 norm／残差、QKV／gate 投影、KV 写入和通信融合，TP8 GB200 上 batch-1 的单步前向从初始近纯 PyTorch 版 **8.95 ms 降至 3.30 ms**，8×2K prefill 从 **328 ms 降至 176 ms**。这是对团队自身未优化首版的对照，不能当作跨模型优势。

**推测解码的有效区间。** DFlash2 在 TP8 的低熵 SPEED-Bench 代码/排序任务上，单请求约 **708 输出 tokens/s**、平均接受长度 3.7；自适应验证在并发 128 时由 15,012 升至 16,632 tokens/s（+10.8%），并发 1～8 基本中性。开放式聊天可能有更低接受率，文章的 AgentX“每卡 88K 总 tokens/s”又计入大量缓存输入，不能误写成生成速度。首日镜像与命令给出了可运行路径，但黑盒 benchmark 仍需按自己的负载核对。**投入建议：立即学习（2～3 小时）。** 若考虑部署昨日的 Beam 权重，先按官方配方跑同硬件基线，再分别开关 DFlash2 和自适应验证，记录真实接受率、TTFT、TPOT 与质量。

# 科研进展

### 可验证搜索发现新的可逆量子电路结构

**质量：A｜重要性：中｜Personal Utility：中｜Evidence Maturity：M0｜论文首版：2026-10-16（北京时间）。** Anthropic 与合作者的[论文](https://arxiv.org/abs/2610.22367)和[研究说明](https://www.anthropic.com/research/designing-efficient-quantum-circuits)把模型提出的电路送入独立程序校验器，先查正确性，再按 Toffoli 门和 qubit 资源评分；八类计算基元中，论文称七类同时改善门数与 qubit 数。最有结构增量的是模逆：传统 divsteps 在可逆计算中需要保留分支历史，作者设计从运行状态反推出分支的方式，并用数值模拟与 Lean 证明关键性质。其一个点加法配置相对此前最省 qubit 的设计，**多用 12% qubit、少用 17 倍门**；这是特定 Pareto 点，不能概括为所有资源同时缩小。

**判断边界。** 结果依赖任务能被程序可靠验证，论文给的是逻辑电路资源，不包括容错编码、物理 qubit、编译映射和真实量子设备耗时。论文刚发布，复现资产与独立核算仍需继续检查；但方法本身对 AI 系统有启发：让 Agent 搜索候选，由独立验证器守住正确性，再按多目标资源而非单一分数选 Pareto 解。**投入建议：了解即可。** 可读论文的 divsteps 证明与资源表，观察其证明脚本、成本模型和外部复核是否公开后再决定深读。
