## Part 2/3

# 系统与编译器进展

### CUDA Rust：NVIDIA 同时推进 SIMT 编译器与 tile DSL

**重要性：高。** NVIDIA 公布两条原生 Rust GPU kernel 路线。[cuda-oxide](https://github.com/NVlabs/cuda-oxide) 是自定义 `rustc` codegen backend，把 Rust MIR 经 Pliron IR、LLVM IR 编译为 PTX；host 与 device 可写在同一文件，并用 launch contract、`DisjointSlice` 等类型约束表达索引和别名安全。[cutile-rs](https://github.com/NVlabs/cutile-rs) 则在稳定版 Rust 上提供 tile-level DSL，宏在编译期捕获 AST，运行时通过 CUDA Tile IR JIT 编译，更接近高层矩阵分块编程。[NVIDIA 技术文章](https://developer.nvidia.com/blog/introducing-cuda-rust-two-tracks-for-writing-gpu-kernels/)

两条路径的取舍很清楚：cuda-oxide 保留 SIMT 控制力，适合研究编译器、warp/cluster 操作和精细内存语义，但目前依赖 pinned nightly、Linux、CUDA 12+ 与计算能力 8.0+；cutile-rs 使用稳定 Rust 1.89+，并已被 Hugging Face Grout、mistral.rs 使用，但需要 CUDA 13.3，抽象层更高。两者都仍处早期阶段，API 会变化，不能据此推断生产成熟度或普遍性能优势。

**建议投入：立即学习（1～3 小时）。** 先对照阅读两条编译流水线和最小 kernel 示例，再重点看 cuda-oxide 的 codegen/runtime 边界与 cutile-rs 的 host-side ownership、Tile IR JIT。若有 NVIDIA 环境，可各跑一个矩阵乘示例并记录编译时间、kernel 性能和生成 PTX；没有对应 CUDA 版本时，先做代码走读，不建议为早期工具链投入半天搭环境。

### LLVM 23.1.1 发布

**重要性：中。** LLVM 项目首页在 9 月 8 日发布 23.1.1。它是 23 系列维护版本，本期可确认的是版本可用性，官方首页没有把它描述为一次重大架构更新。使用 LLVM/Clang 23 或下游编译器工具链的项目应先阅读 release notes、跑 ABI 与后端回归，再安排升级。[官方发布页](https://llvm.org/)

# GitHub 高价值项目洞察

### NVlabs/cuda-oxide：从 Rust MIR 到 PTX 的完整实验栈

[官方仓库](https://github.com/NVlabs/cuda-oxide)不是概念样例：它包含 codegen backend、host runtime、device intrinsics、文档、示例和测试，流水线可追到 Rust MIR → Pliron IR → LLVM IR → PTX。对编译器方向最有价值的是，它把 kernel launch 的参数布局、别名约束和 GPU 内建操作纳入 Rust 类型与编译期策略，而不是只包一层 CUDA FFI。

项目仍标注 experimental，依赖 nightly Rust，当前兼容范围和生产稳定性有限；现有关注度不能替代跨 workload 的独立 benchmark。**建议投入：立即学习（1～3 小时）**，从 `cuda-oxide-codegen`、`cuda-core` 和 book 的最小示例建立端到端调用图，再判断是否值得做本地 microbenchmark。

### ifm-ai/uno：训练、推理与检查点资产已经齐备

[Uno 仓库](https://github.com/ifm-ai/uno)包含 `nano_vllm_uno` 推理引擎、linear/tree sampler、conditional-LoRA 训练、评测脚本、示例和多个检查点，已超过“论文加 README”的门槛。它适合用来核对无损采样机制在真实 batch、KV-cache 压力和硬件条件下是否仍有收益；tree sampler 对 FlashAttention/Hopper 等环境的依赖需要单独检查。**建议投入：立即学习（1～3 小时）**，先复现小模型正确性，再在固定输出分布约束下测延迟—吞吐 Pareto，不要直接照搬论文峰值。

## Part 3/3

# 科研进展

### Uno：用离散扩散为自回归 LLM 提供无损加速

Uno 在冻结基础自回归模型权重的同时训练轻量扩散参数，并用 Ψ-Spec 采样器生成候选；接受/拒绝过程被设计为保持原自回归模型的目标分布，因此“无损”指分布等价，而不是近似保持任务准确率。作者在 8B 规模实验中报告最高约 3× 加速，并称不需要独立 draft model；项目页给出的系统 Pareto 图则显示最高约 2.5×，具体收益显然依赖 batch、采样器和设备。[论文](https://arxiv.org/abs/2609.04010)｜[项目页](https://s-sahoo.com/uno/)

**质量：B；证据成熟度：M1。** 论文原始发布于 9 月 3 日，本期按代码、训练 recipe、评测脚本和检查点证据补充纳入。优点是“冻结基础模型 + 额外扩散能力”避免同时维护一个独立 draft 模型，并给出了可以审查的推理实现；风险是结果仍主要来自作者，缺少第三方复现、生产 serving 集成以及不同 batch/KV-cache 压力下的完整数据，和既有 diffusion-augmented LLM 路线的差异也需要进一步核对。

学完后可以建立“draft-free speculative decoding”与离散扩散模型之间的统一理解，并能区分分布无损、任务精度不降和端到端吞吐提升这三个不同命题。**建议投入：立即学习（1～3 小时）**，先读 Ψ-Spec 的正确性条件，再走读 `nano_vllm_uno` 的 sampler 和 benchmark；只有在复现分布一致性后，才讨论峰值加速是否可迁移到自己的 serving 负载。

# 本期最值得关注

1. **CUDA Rust 双路线。** 它把 Rust 类型系统、GPU kernel 抽象和编译流水线放进了同一套可运行资产，最适合用来理解低层 SIMT 与高层 tile DSL 的真实边界。建议投入 1～3 小时，对照走读 cuda-oxide 与 cutile-rs 的最小 kernel 和编译路径。
2. **Uno。** 它提供了少见的“保持目标分布不变、又不需要独立 draft model”的加速方案，并已有代码和检查点。建议投入 1～3 小时核对采样正确性与实际延迟—吞吐曲线，等待第三方复现后再评估生产价值。
