# 系统与编译器进展

### SWE-Serve 揭示“本地测试通过”与“真实服务可用”的落差

[NVIDIA 技术文章](https://developer.nvidia.com/blog/how-swe-serve-exposes-the-gap-between-local-tests-and-live-serving/)与[论文](https://arxiv.org/abs/2609.26777)从 83 个已合并 SGLang PR 构造 53 个推理工程任务，其中 12 个 CPU、41 个单 H100 任务，覆盖端到端执行、持久状态和并发请求。作者对 627 个补丁的复验显示，仅检查本地测试时通过率为 69.4%，加入 live-server verifier 后降至 45.9%，147 个补丁发生“本地过、在线失败”的翻转；跨 runtime 任务通过率 47.7%，也低于单域任务的 69.0%。这组数据说明推理基础设施 Agent 的关键瓶颈已不是单文件修补，而是服务生命周期、协议与状态交互。局限是任务全部来自 SGLang，榜单与 verifier 仍由作者团队发布。建议投入：**立即学习（1～3 小时）**，优先审查 live-server verifier 与失败翻转样本。

### B200 机密计算推理把性能损失压到低个位数

[NVIDIA 官方测试](https://developer.nvidia.com/blog/enabling-private-high-performance-production-ai-inference-with-nvidia-confidential-computing/)在 8×B200、TensorRT-LLM、DeepSeek-R1、32K 输入/1K 输出条件下比较普通模式与 Confidential Computing，报告并发 1～16 时输出吞吐保留 96.1%～98.2%，每输出 token 时间开销为 1.2%～4.3%。工程上为加密 bounce buffer 改用 pageable host memory，并通过异步 D2H readback、`%globaltimer` 调优计时和通信算法选择规避 CC 环境限制。结果说明整机可信执行不必必然付出两位数推理损失，但当前数字来自单一厂商、单一模型与特定硬件栈，且 NVLS 在 B200 CC 下不可用。建议投入：**了解即可（5～20 分钟）**；有敏感数据推理需求时再按自身并发与网络拓扑复测。

### Topograph 把集群互联拓扑转成调度器可消费状态

[NVIDIA Topograph](https://developer.nvidia.com/blog/topology-aware-workload-scheduling-with-nvidia-topograph/)从云 API、InfiniBand、Spectrum-X 或 Multi-Node NVLink 发现拓扑，归一化后输出 Kubernetes node labels、Slurm 配置、Slinky ConfigMap 或图数据，并在节点与 Pod 变化时重新生成。项目覆盖多家云提供商，支持 KAI Scheduler 的 topology-aware gang placement，还提供 Helm、Deb/RPM 与无生产硬件的模拟工具。它解决的是拓扑信息维护这一容易被忽略的调度前置条件，而不是直接证明吞吐增益；实际收益仍取决于 provider 数据准确性、触发时效和 workload 通信模式。建议投入：**了解即可（5～20 分钟）**，多机训练或推理集群可进一步做碎片率与跨域流量 A/B。

**质量：B；证据成熟度：M1；个人价值：高。** 仓库公开 53 项 Harbor 格式任务、隐藏 verifier、参考解、oracle/nop 校验、closed-book 网络隔离及三次运行配置，任务要求不止修改代码，还要在真实 SGLang 服务中通过持久状态、并发和端到端请求检查。复跑门槛较高：完整集合需要单张 H100、至少 128 GiB 主存和约 700 GB 磁盘；仓库目前只有初始提交，尚无独立榜单、任务缺陷修订记录或跨 runtime 版本。**建议投入：立即学习（1～3 小时）**，先在 CPU 子集复跑一个本地通过但 live server 失败的样本，把 verifier 设计迁移到自己的系统 Agent 评测。

# 科研进展

### CliffCompaction：不重写历史的长任务自动压缩

[论文](https://arxiv.org/abs/2609.26779)与[作者仓库](https://github.com/nguyenvuthientrang/cliffcompaction)提出透明 API 代理：超过 token 阈值时保留系统/任务头与最近轮次，长工具结果删除、工具调用压成签名，但默认保留助手文本；后续压缩始终从原始历史重建，不对旧摘要再次摘要，以减少累积漂移。作者报告 Terminal-Bench 成本最高下降约 50%，KernelBench 在 200/400 步长轨迹的收益分别达 2.23 倍/3.58 倍。**质量：B；成熟度：M1；个人价值：高。** 代码支持 Claude Code 与 Codex、shadow 模式和失败透传，但工具结果删除可能抹去关键证据，实验也尚无第三方复跑。建议**立即学习（1～3 小时）**，先用 shadow 模式审计哪些观测会被删除，再比较任务成功率—token 成本 Pareto。

### AIDE²：研究 Agent 连续八天改进自身

[论文](https://arxiv.org/abs/2609.26457)报告 AIDE² 在八天自主运行中完成七轮对研究 Agent 的改进，并在冻结的留出问题上观察到总体泛化收益；作者还将奖励投机作为显式审计对象，称人工复核后的相关比例由 55% 降至 32%。**质量：B；成熟度：M0；个人价值：高。** 这是递归自我改进方向中较长时程的实证案例，但目前尚未确认官方代码、完整轨迹、冻结评测集或可重复 recipe，单次作者实验也难排除搜索偏差与评测适配。建议**了解即可（5～20 分钟）**，等待资产公开和独立同预算复现。

# 本期最值得关注

1. **SWE-Serve 把推理工程 Agent 的验收从单元测试推到真实服务。** 69.4% 到 45.9% 的落差直接量化了本地测试盲区；最值得借鉴的是 verifier 如何覆盖服务启动、持久状态与并发，而不是先追逐榜单名次。
2. **CliffCompaction 提供可审计的上下文压缩基线。** 它以删除/截断和原始历史重建换取成本下降，设计比递归生成摘要更容易定位错误；实际采用前应先用 shadow 模式检查关键工具证据是否会丢失。
