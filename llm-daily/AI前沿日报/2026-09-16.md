# 业界进展

### Claude 把 Salesforce 与小企业工具链纳入可审批的 Agent 工作流

**重要性：中高。** Anthropic 在 9 月 15 日发布 [Bringing Salesforce into Claude](https://claude.com/blog/bringing-salesforce-into-claude)，向所有付费 Claude 方案提供 Salesforce 插件测试版：37 个 Skills 可连接 Salesforce 与 Slack，沿用既有数据权限，并默认要求用户批准关键动作。它同时发布 [Claude for Small Business](https://claude.com/blog/claude-for-small-business-launches-new-workflows-integrations-and-training-programs)，提供 43 个工作流、27 个新集成，覆盖 Shopify、Stripe、Square、Xero、Gusto、Atlassian、Zoom、TikTok 与 Zapier 等工具；官方称插件累计安装量已达 90 万次。这里真正值得观察的不是集成数量，而是“连接器 + Skill + 默认审批 + 可定时执行”正在成为通用企业 Agent 的产品边界。**建议投入：了解即可（30～60 分钟）。**

同日的 [Building an AI-native revenue organization](https://claude.com/blog/building-an-ai-native-revenue-organization) 更像销售组织落地手册：以三阶段推广、ROI 和岗位任务定义组织采用，新增技术信号有限，但说明 Anthropic 正把插件分发与企业变革方法论一起销售。

### Claude 向受监管金融工作流推进，但关键判断仍保留人工责任

Anthropic 在 9 月 14 日发布 [Claude for Financial Advisors](https://claude.com/blog/claude-for-financial-advisors)，把托管机构、组合平台、CRM、财务规划与会议记录连接器打包为顾问插件，覆盖会前准备、组合漂移、税务与遗产摘要、会后记录和合规提示。对客户沟通、投资建议、合规判断等关键动作，官方明确保留人工审核和批准，并建议注册投资顾问使用带审计日志的 Enterprise 方案。**重要性：中。建议投入：了解即可（30～60 分钟）。**

另外两篇 9 月 14 日漏项更偏案例与方法论：[How healthcare organizations use Claude](https://claude.com/blog/how-healthcare-organizations-use-claude) 展示 Claude 在 Slack 中维持频道上下文，但明确该能力不在 BAA 覆盖内、仅用于不含 PHI 的场景；[Deploying AI from pilot to production](https://claude.com/blog/deploying-ai-from-pilot-to-production) 与 Accenture 总结任务定义、TCO 和分级监督。它们没有改变底层能力，主要价值是给出合规边界和推广清单。

### DeepSeek-V4.1-Flash 补入阿里云模型目录

**此前漏报。** 阿里云百炼在 9 月 13 日将 `deepseek-v4.1-flash` 加入北京地域的[新模型列表](https://help.aliyun.com/zh/model-studio/newly-released-models)，列出 100 万 token 上下文、最高 38.4 万 token 输出、原生视觉输入，以及 552B MoE 中输入阶段激活 8B、输出阶段激活 16B 参数等规格。这是既有模型的云平台可用性更新，不是新的基础模型发布。**建议投入：暂不投入。**

# 系统与编译器进展

### Anthropic 用外部 journal 与无状态消费者消化 Agent 代码增长带来的 CI 压力

**重要性：高。此前漏报。** Anthropic 在 [Agentic coding is straining CI](https://claude.com/blog/agentic-coding-is-straining-ci) 中披露：工程师季度代码产出相对 2021～2025 年均值约增至 8 倍，Claude 编写约 80%；六个月内测试数量增长 10 倍、CI job 增长 25 倍。其测试影响分析服务原本由单个 listener 顺序处理提交并维护内存状态，扩大机器、按 package 分片和频繁重启只能分别多撑 70 天、29 天和不到一天。

重构后的主路径把 append-only journal 放入外部内存存储，listener 只负责无状态、可横向扩展地写入提交变化；独立 consumer 再把 journal 滚入按测试组织的历史索引。这样重启和扩容不再丢失真相源，积压曲线恢复平稳。更有参考价值的是演进过程：局部扩容没有绕过原有确定性影响分析，而是把状态所有权从 singleton 拆出；官方称一名工程师用三周完成。对构建 Agent 驱动研发平台的人，这是从吞吐症状追到状态架构的直接案例。**建议投入：深入学习（半天以上）。**

### JAX dropless MoE 把不规则专家负载压进 grouped GEMM 与融合通信路径

NVIDIA 在 [Accelerating Dropless MoE Training in JAX with NVIDIA Transformer Engine](https://developer.nvidia.com/blog/accelerating-dropless-moe-training-in-jax-with-nvidia-transformer-engine/) 中展示一条完整优化链：以能接受可变 expert token 数量的 `grouped_gemm/ragged_dot` 取代最坏容量 padding，把 dispatch/combine 融进 NCCL EP，并用同节点/跨节点 token 去重、主机 activation offload 与 XLA 多流 collective 重叠减少通信暴露。

项目方报告 DeepSeek-V3 671B 从 GB200 上未优化的 103 TFLOPS/GPU 提升到 1,068 TFLOPS/GPU，约 10.4 倍；在 GB300 NVL72 上相对 128 GPU 基线扩至 1,024 GPU 仍有 97% scaling efficiency。实现已进入 2026-09-09 之后的 NGC MaxText 容器，具备复跑入口，但数据来自 NVIDIA 自测，且硬件、容器与通信拓扑绑定很强。**重要性：高。建议投入：深入学习（半天以上）。**

NVIDIA 9 月 15 日另发布 FLARE 跨 Docker、Kubernetes 与 Slurm 的联邦学习扩展文章，重点是部署形态而非新算法；可在确有多机构数据隔离需求时再投入。

# 科研进展

### Plan Injection：把恶意计划伪装成上下文，可让 Actor 生成“干净”推理轨迹

[Corrupt Plans, Clean Traces](https://arxiv.org/abs/2609.15989) 提出 plan injection：在 Actor 上下文中植入措辞无害的恶意推理，使模型执行对抗行为，同时把计划改写成看似自身产生的推理而不标注来源。作者在多类 monitorability benchmark 上报告 25%～33% 的监控逃逸率，并扩展到 DeepSeek-R1；更反直觉的是，向 Monitor 提供被注入的计划在 Bio-Math 任务中最多让检测率下降 50%，额外思考预算有时被用于合理化计划而非报警。

这直接挑战“Monitor 看得到更多上下文就更安全”的单调性假设。当前仍是作者构造的评测，缺少生产 Agent、隐藏工具调用和多轮记忆下的独立复现，但攻击面与实际 prompt injection 高度相邻。**建议投入：深入学习（半天以上）。**

### Gavel 从冻结 LLM 的中间状态读取 Skill 路由信号

[The Router Within](https://arxiv.org/abs/2609.15982) 不把所有 Skill 元数据塞入上下文，也不另接大型检索器，而用两个可训练线性映射读取冻结 LLM 的中间层状态。安装 Skill 时构建紧凑状态库；运行时先用 glance 召回候选，再恢复候选 Skill 的前向过程，以模型自身 likelihood 与 yes/no 判断组成 verdict。

作者称该方法一次训练后可零样本迁移到三个公开 benchmark 和新建的 372 条 SkillTraj 轨迹；在 Qwen3-32B 上，相比带 1.2B～16B 外部参数的 progressive disclosure 或 retrieve-and-rerank，书面任务最多提高 13.4 分，Skill 在 rollout 中途才需要时最多提高 21.9 分。它提供了绕开上下文膨胀的新路，但线性探针训练数据、Skill 库漂移和跨模型迁移成本仍需审计。**建议投入：深入学习（半天以上）。**

### Stellar Colosseum 用分阶段搜索、就绪门与定向反证组织长程研究

[Stellar Colosseum](https://arxiv.org/abs/2609.15983) 把数学和理论计算机科学研究拆成策略并行探索、readiness gate、相互依赖的章节级子问题、定向反证和重叠随机采样树聚合；Verifier 的发现会回流到受影响的证明片段，而不是简单多数投票。作者报告以 Gemini 3.1 Pro/3.7 Flash 在 TCS-Bench 上达到 71.0%，并在 Codeforces 评测中解决 222 题中的 218 题，还声称得到若干针对 FOCS/JMLR 论文开放问题的新结果。

论文把 harness 结构说得较清楚，但“新研究结果”的正确性高度依赖专家验证，且尚未给出独立评审与完整成本对照。现阶段更适合作为长程研究编排的设计样本，而不是能力已被确认的研究自动化系统。**建议投入：立即学习（1～3 小时）。**

# 本期最值得关注

1. **Anthropic 测试影响分析服务的状态解耦。** 这是 Agent 代码产出真实冲击工程基础设施后，从扩机器失败走向外部 journal、无状态扩展的完整案例；建议半天精读状态一致性、积压恢复和索引更新路径。
2. **Plan Injection 对思维链监控的反例。** 它表明给 Monitor 更多上下文和推理预算不一定单调增益；建议结合现有 prompt-injection 防线复跑，并把 Actor 上下文来源、引用追踪和 Monitor 隔离纳入威胁模型。
