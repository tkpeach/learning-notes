# 系统与编译器进展

### 此前漏报：lld 23 将更多 ELF 链接阶段并行化，同时暴露新的正确性边界

**重要性：高。** MaskRay 于 9 月 12 日发布的 [lld 23 ELF changes](https://maskray.me/blog/lld-23-elf-changes) 汇总了 release/23.x 分支点到 23.1.0-rc1 之间的 141 个 lld/ELF 提交，上一周期为 72 个。性能主线包括并行加载输入文件、并行 `--gc-sections` 标记、把 relocation scanning 改成各目标专用的可内联 scanner，以及降低 LLVM 并行运行时的任务开销。作者在同一台 i7-14700K、统一构建参数、8 个性能核和 10 次测量下，对九个真实 release-mode 链接任务测得 lld 23.1 相对 22.1.8 加速 1.04～1.23 倍；收益最低的 TensorFlow 和 Chromium 分别被单线程 symbol-version glob 与 ICF 阶段主导，给出了明确的后续瓶颈。

更重要的是并发化的代价边界：并行输入加载一度让 `--reproduce` 输出失去确定性，并行 relocation scan 也暴露了 `addRelativeReloc` 数据竞争，后者通过能被 ThreadSanitizer 捕获的测试修复。lld 23 还新增 x86-64 CFI jump-table relaxation；符合保守条件时把小函数体搬入 jump table 或消除末项跳转，提交数据称可减少 0.2～0.5 个百分点 CFI 开销。与此同时，长期无人采用的 symbol partition 被移除，多项 linker-script、DWARF、TLS 和 GNU ld 兼容性问题得到修正。

文章最后给出一条对 AI 编程尤其现实的结论：本周期新贡献者和带明显 Agent 痕迹的 PR 增多，但错误根因、未经设计讨论的大补丁、未运行测试和冗长说明把成本从贡献者转移给维护者。学完后能更具体地理解链接器并行化的任务切分、负载均衡、确定性与 race 检测，也能为 AI 辅助的编译器贡献建立“小补丁、复用现有测试、先跑本地验证、设计先于代码”的准入清单。**建议投入：立即学习（1～3 小时）。** 优先读 Performance、CFI jump table relaxation 和 AI-assisted patches；若维护构建链，再逐项核对 breaking changes 与 linker-script 兼容性。
