# AI 前沿日报｜2026-09-12

## Part 1/3

# 今日总览

今天最值得关注的不是新模型，而是几条很具体的系统路径：OpenAI 公开了支撑十亿级用户的在线存储平台 Habitat，展示 Python 服务如何在超大规模下处理尾延迟、连接池和下游保护，并最终迁移到 Rust；SGLang 则给出了 DeepSeek-V4.1 新架构落到 serving 与 RL 栈时的工程实现。两者共同说明，模型能力之外，真正决定系统上限的是可预测的接口、跨层状态复用、资源隔离和可验证的正确性边界。

对个人学习最有价值的新代码资产是 HyQuant。它没有把全部注意力状态一刀切成低比特，而是保留少量高影响 token 和局部窗口的高精度，再用融合 Triton kernel 把其余 KV cache 压到 K4V4；这是一份适合从算法假设一路追到 kernel、缓存布局和端到端收益的紧凑样本。

# 业界进展

### OpenAI Habitat：十亿级用户在线存储从 Python 走向 Rust

**重要性：高。** OpenAI 公开了在线存储平台 [Habitat](https://openai.com/index/scaling-storage-one-billion-users-part-one/) 的第一阶段演进：平台目前承载每秒超过 7000 万请求、500 PB 以上数据，并服务每周超过 10 亿用户。Habitat 最初是直连 Azure Cosmos DB 的 Python 客户端库，随后被抽成统一服务，以集中处理路由、权限、加密、限流、数据驻留和连接池；它刻意只暴露可预测、常量工作量的 NoSQL 接口，把复杂分析查询隔离到 CDC 下游。

最有复用价值的是失败模式：CPU 型后台任务会放大 `asyncio` 调度延迟；无抖动的配置轮询会让同一 pod 的多个 worker 同时停顿；`aiohttp` 的 LIFO 连接复用又可能把新流量持续压回已经变慢的进程，形成亚稳态故障，改为 FIFO 后才打破反馈环。OpenAI 随后用两名工程师配合 Codex 和 GPT-5.5 在 2026 年第二季度将服务重写为 Rust；新服务已承载 95% 的生产请求，官方报告 CPU 效率提升 6 倍、内存效率提升 15 倍。学完后能更系统地诊断异步服务的尾延迟、负载倾斜和惊群，并为“先稳定接口、再换实现语言”的迁移排序；也能把事件循环延迟、连接复用策略和下游连接预算纳入自己的服务基线。**建议投入：立即学习（1～3 小时）。** 优先读 `asyncio` 延迟、LIFO→FIFO 亚稳态故障、下游保护和 Rust 迁移四节，产品背景可以略读。

## Part 2/3

# 系统与编译器进展

### SGLang/Miles：DeepSeek-V4.1 的 serving 不只是“加一个模型类”

**重要性：高。** [SGLang 与 Miles 的 Day-0 实现说明](https://www.lmsys.org/blog/2026-09-10-deepseek-v41)把 DeepSeek-V4.1 的架构约束映射到了运行时：每层保留最近 128 个位置的 FP8 滑窗 KV，四个源层生成跨层共享的压缩 KV 与 indexer key，查询最多选择 512 个压缩位置；后续层复用候选与选择结果。两张共 189 GiB 的 FP8 Engram 表既可放 HBM，也可下沉主机内存；在 4×GB300 的作者配对测试中，主机分片加 huge page 让 KV cache 容量增加 36%，decode 吞吐和 TTFT 基本相当，28 条 greedy probe 与基线一致。

工程重点是 bounded replay 和正确性边界：prefix cache 只保留压缩状态，命中后重算前缀末尾 128 个 token 来恢复滑窗 KV；上层 prefill 也只计算每个请求的末尾窗口，以有限重算换存储。学完后能理解共享 KV、稀疏检索、外存随机访问和 prefix reuse 如何共同决定 serving 设计，并能为新模型建立“架构语义→缓存状态→内核→一致性探针”的接入清单。**建议投入：立即学习（1～3 小时）。** 先读 cross-layer sharing、Engram placement 和 bounded replay，再核对 SGLang 中对应实现；不要只看最终吞吐数字。

### 此前漏报：CUDA 13.4 强化共享 GPU、跨 NVLink 传输与位置感知

**重要性：高。** NVIDIA 于 9 月 9 日发布 [CUDA Toolkit 13.4](https://developer.nvidia.com/blog/cuda-toolkit-13-4-adds-windows-on-arm-support-and-greater-control-over-shared-gpus/)：除 Windows on Arm 和 Rubin（SM 107）预览外，MPS v3 新增脚本化 CLI、命名实例、namespace、TOML、SM 分区和基于 cgroup 的显存上限；新的 CUDA Compute Fabric Transport 允许通信库通过逻辑 endpoint 在 NVLink fabric 上发起异步 put/get/reduce，避免把所有远端分配映射进本进程虚拟地址空间。运行时还可查询 locality domain 和统一内存驻留位置，安装包开始把驱动与 Toolkit 解耦。

对 C++/GPU 工程更直接的变化还包括 GCC 16、Clang 22 支持，`cuda::std` 并行算法、CCCL 3.4 的单调用 CUB API，以及 Tile IR 的 Programmatic Dependent Launch。学完后能更准确地区分 MPS 资源治理、CFT 通信原语和 NCCL/NVSHMEM 的职责，并评估 locality/驻留信息是否值得进入调度器。**建议投入：了解即可（5～20 分钟）。** 先读 MPS v3、CFT、locality 和驱动拆分；只有在维护通信库或共享 GPU 平台时再深挖 API。

### 此前漏报：Dynamo 将多模态 Encode 与 Prefill/Decode 解耦

**重要性：中。** NVIDIA 的 [EPD disaggregation 实验](https://developer.nvidia.com/blog/when-to-use-encode-prefill-decode-disaggregation-to-accelerate-multimodal-model-serving/)让 vision encoder 独立排队、批处理和扩缩容，再经 NIXL 把 embedding 交给 prefill/decode worker。作者在 Qwen3.5 122B-A10B NVFP4、4×GB200 等配置上报告：每请求 10 张图、输出 1024 token 时，共置 encoder 的 TTFT 降低 58%，异构 encoder tier 在相同延迟 SLO 下 goodput 提升 70%；50:50 文本/图像流量中，文本与图像平均 TTFT 分别下降 42.2% 和 30.8%。

它不是普适加速：输出变长后 decode 占主导，共置方案在轻图像、输出 2048 token 时反而回退 2.5%；27B dense 模型的共置 goodput 也只有聚合方案的 0.65 倍。学完后能用 ViT/LLM 计算占比、输出长度、流量混合和硬件异构性判断是否值得拆分，而不是机械套用 disaggregation。**建议投入：了解即可（5～20 分钟）。** 重点看决策表和负收益区域；只有业务确有高媒体负载时再跑 Dynamo 复现实验。

# GitHub 高价值项目洞察

### HyQuant：把注意力敏感位置留在高精度，把其余 KV cache 压到 4 bit

[jerrysfls/HyQuant](https://github.com/jerrysfls/HyQuant)是 EMNLP 2026 Main 论文 [HyQuant](https://arxiv.org/abs/2608.27875) 的官方实现。它维护按列累积的 attention score，每 64 个 token 更新一次，保留约 top-5% 的“垂直线”key 和局部窗口为 FP16/BF16；其余 prefill 计算走低精度融合 Triton attention，decode 则把大部分 KV cache 存成 K4V4，并把反量化、online softmax 和 attention 融进同一 kernel。作者报告 top-5% 加 128-token 窗口可覆盖 80% 以上注意力质量；在 Qwen3、Llama 3.1、GLM-4 的 LongBench 等任务上接近全精度。

**质量：B；证据成熟度：M1。** 仓库有 Qwen/Llama/GLM patch、Triton kernel、混合 KV cache、评测与 smoke test，是真实可运行实体。作者在单张 H100 80GB 上报告 decode-attention kernel 加速 1.32～3.58 倍，但端到端 decode 仅提升 1.04～1.17 倍；垂直线检测占 3%～5% 运行时间，保留 5% 高精度 token 又让缓存比严格 4-bit 大约多 15%。目前仓库仅有少量提交，尚无第三方复现，也没有 vLLM/SGLang 生产集成。

学完后能把低比特误差从“统一量化问题”重构为“结构化少数敏感位置的保精度问题”，并能实际修改注意力 kernel、缓存布局和模型 patch。**建议投入：立即学习（1～3 小时）。** 先跑 `script/smoke_test_model.py`，再沿 `src/patch` 追到 `src/ops/decode_d_stage.py` 与 `d_stage_kv_cache.py`；先复核单个 Qwen3 模型的质量—显存—延迟三角，不必一开始复跑完整 LongBench。

## Part 3/3

# 科研进展

### NCP-ArchPreview：把 next-concept prediction 接到标准自回归预训练上

[NCP-ArchPreview 技术报告](https://arxiv.org/abs/2609.10715)在 next-token prediction 之外，直接从模型隐状态构造 product-quantized 离散概念词表，再由独立 Concept Module 预测未来概念，并把概念表示反馈给 token 层联合训练。作者将模型扩到 8.9B 参数、用 Dolma-3 的 5.73T token 训练；报告只用 OLMo-3-7B 总训练 token 的 51.3% 即达到其最终预训练 loss，完整训练后下游宏平均高 2.45 分、GSM8K 高 5.99 分。只更新 17M 参数的 VQ 模块还提供了轻量领域适配入口，并能让 DFlash2 drafter 的平均接受长度提升 4.17%。

**质量：B；证据成熟度：M1。** 规模和消融比一般 latent-language-model 工作更扎实，也已公开模型资产；但仍是作者首发结果，尚缺独立复现、完整训练代码和对“参数量增加”与 NCP 目标贡献的外部拆分。学完后能理解多 token 潜变量目标如何与标准 AR 解码共存，以及 latent space 是否能同时服务预训练、适配和 speculative decoding。**建议投入：了解即可（5～20 分钟）。** 先读 concept vocabulary、联合目标和参数对齐消融，等待训练 recipe 或第三方结果后再投入复现。

### EvoSafeHarness：冻结模型，搜索可执行的 Agent 安全外壳

[EvoSafeHarness](https://arxiv.org/abs/2609.05903)不微调受保护模型，而是针对具体模型与领域联合搜索自然语言策略和三个可执行 hook：`system_prompt_transform`、`on_pre_tool_call`、`on_post_tool_call`。外层循环用失败轨迹驱动 Designer、Criticizer、Cascade 和 Analyzer；其中 fresh-context 对手专门排除记住 benchmark 字面量的规则。作者报告在 DecodingTrust-Agent 上将平均攻击成功率从 45.6% 降到 10.0%，utility 只损失 3.3 点；在 AgentDojo 上达到 82.8% utility、0 ASR，并在自适应 PAIR 攻击下把平均 ASR 控制在 20% 以下。

**质量：B；证据成熟度：M1。** [官方仓库](https://github.com/SaFo-Lab/EvoSafeHarness)提供 finance、filesystem、telecom 三类领域、冻结划分、评测平台和可运行的 hook bundle，但当前只有很短的提交历史，复现还依赖 DecodingTrust-Agent、Docker、模型与 judge 凭证。学完后能把 Agent 安全从单次 prompt 过滤提升为带状态的工具调用策略，并能为自己的 harness 建立“效用－攻击成功率－误拒绝”评测。**建议投入：了解即可（5～20 分钟）。** 先看三 hook 契约、held-out 划分和 cascade 评分；等第三方复现或准备实际安全评测时再跑完整搜索。
