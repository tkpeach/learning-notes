# 业界进展

### DeepSeek-V4.1-Flash：用 CED 重构长上下文 KV-cache 成本

**重要性：高。** DeepSeek 发布并开放 [DeepSeek-V4.1-Flash](https://deepseek.com/news/deepseek-v4-1-flash/)：552B MoE 骨干在 prefill 阶段每 token 激活 8B 参数、decode 阶段激活 16B，原生处理图像与文本，并支持最长 1M 上下文。核心变化是 20 层因果编码器加 20 层解码器的 Causal Encoder–Decoder（CED）：解码器各层不再分别从自身隐状态保存全局 KV，而是从编码器最终隐状态投影共享的全局 KV；SWA Bounded Replay 只重放最近窗口来重建缺失的滑窗状态。官方称全局 KV-cache 每 token 占用约为 V4-Flash 的四分之一、V1 的 1/437，持久化 KV footprint 约为 V4-Flash 的八分之一。

训练侧是从头训练的 45T token 多模态语料，在 34T token 时扩展到 1M 上下文；后训练算法仍是 SFT → RL → on-policy distillation，主要增量在 Agent 任务、环境和 rollout 的自动合成数据管线。模型支持 1～100 连续 reasoning effort；[官方模型仓库](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash)已提供 MIT 权重、技术报告、评测与推理目录，并给出 Transformers、vLLM、SGLang 路径。性能与成本结论仍以官方评测为主，510GB 级仓库和新架构也意味着部署兼容性、真实并发收益及 1M 上下文质量需要第三方复核。

### Anthropic：AI 滥用从“助手”转向“执行编排器”

**重要性：高。** Anthropic 的 [2026 年 9 月威胁情报报告](https://www.anthropic.com/threat-intelligence-report-september-2026)汇总了 2025 年 12 月至 2026 年 8 月间被其干预的网络攻击、影响行动、监控、诈骗、生物与武器滥用案例。最重要的趋势是：多数被披露的网络行动已经让模型直接执行或编排侦察、钓鱼、漏洞利用、持久化和数据外传，人类更多负责选择目标及复核结果；部分攻击还用多 Agent 并行扩大吞吐。

报告中的案例经过平台方调查，但并不代表所有滥用的发生率，归因也存在情报分析不确定性。工程上的直接结论是：Agent 安全不能只做输入输出过滤，还必须覆盖凭证隔离、工具最小权限、跨步骤行为检测、速率异常与人工审批；Anthropic 同时说明 ShinyHunters 相关事件使用的是被盗客户 API key，并非 Anthropic 系统遭入侵。

### GPT-Live-1 API：全双工语音从轮次拼接变为单模型交互

**重要性：高。** OpenAI 发布 [GPT-Live-1](https://openai.com/index/introducing-gpt-live-1-in-the-api/)，让模型能够同时听取和说话，直接处理背景噪声、沉默、打断与长会话，避免传统 STT → LLM → TTS 串联造成的轮次延迟和信息损耗；复杂任务仍可委托给 GPT-6 Astra 或外部后端。官方称其在 Full Duplex Bench 上比 GPT-Realtime-2.1 高 30 个百分点，并在早期真实语音评测中比 turn-based 系统减少约 80% 的误打断。它改变的是实时 Agent 的交互架构，但这些数据仍需在电话链路、口音、噪声和业务工具调用中复测。

# 系统与编译器进展

### OpenAI Agents API：把 Codex harness 变成托管基础设施

**重要性：高。** [Agents API](https://openai.com/index/introducing-the-agents-api/)进入公开测试，开发者通过一次会话定义任务、模型、工具和执行环境，即可使用 Codex 同源的版本化 harness。系统原生提供长会话自动 compaction、按需加载工具定义的 tool search、程序化并行工具调用、MCP、skills/plugins、vault 与多 Agent 编排；执行环境可选 OpenAI 托管 sandbox、自有基础设施或合作伙伴 sandbox。托管 sandbox 能运行代码、处理文件并保存中间产物，API 本身不另收费，成本来自模型 token 与所用工具。

这把 Agent 系统的关键分层变得清晰：模型负责推理，harness 负责上下文、工具和子 Agent 协调，sandbox 负责执行与隔离，业务方保留知识、权限和工作流。学完后可以更有把握地决定哪些能力应自建、哪些可交给托管控制面，并把现有 prompt chain 改造成可恢复的长任务。**建议投入：立即学习（1～3 小时）。** 先读 session、environment、compaction 和 tool search，再用一个只读 MCP 工具做最小任务；随后才开启多 Agent。重点验证失败恢复、幂等性、凭证边界和成本，不必先看客户案例。

# GitHub 高价值项目洞察

### openai/codex：可检查的 Agents API harness 基线

[openai/codex](https://github.com/openai/codex)是成熟的 Rust 主体开源工程，仓库包含 `codex-rs`、CLI、SDK、文档、工具与测试；本期的新触发不是普通版本更新，而是 OpenAI 明确宣布 Agents API 由这套开源 Codex harness 驱动。它因此同时成为托管 API 的行为参考和自建 Agent 控制面的实现样本。

**质量：A；证据成熟度：M4。** 核心代码、长期提交历史和大规模产品采用均存在，但托管服务与公开仓库不会完全等价，具体服务端调度、隔离和运维实现也不都在仓库内。**建议投入：立即学习（1～3 小时）。** 从 `codex-rs` 的会话循环追到工具调用、审批、sandbox 与 compaction 边界，再把这些边界同 Agents API 对照；学完后能设计更清晰的模型—harness—执行环境接口，也能判断托管与自建的真实差异。

### Φ-Bench：85 个可运行的 AI 基础设施工程任务

[Φ-Bench 仓库](https://github.com/one2piece2hello/faibench_Frontier_InfraBench)从 10,000 多个 issue、PR、工程讨论和系统论文候选中筛出 85 个任务：55 个 kernel function completion、20 个长周期仓库实现、10 个端到端系统优化。每个任务提供自包含 Dockerfile，求解与评分离线进行；75 个任务内置待修改仓库，83 个提供参考解，统一 runner 已支持 Codex 与 Claude Code。评分面虽然公开，但测试和 oracle 不会放进求解镜像，并记录了硬件校准 caveat。

**质量：B；证据成熟度：M1。** 它有真实代码、容器、评分器、任务索引和可运行路径，远强于只有题目描述的 benchmark；但刚发布、部分性能 anchor 依赖 H20 或 Sapphire Rapids，尚缺跨硬件复现和长期防污染验证。**建议投入：立即学习（1～3 小时）。** 先运行 `scripts/verify_package.py`，再选一个 CPU 长周期任务和一个可用硬件匹配的 kernel 任务，用同一 Agent 配置比较成功率、时间、token 和失败类型；不要直接全量跑 85 项。学完后可以建立一套贴近 LLM systems 的 Agent 回归评测，并区分局部补全能力与开放式系统优化能力。

# 科研进展

### SWE-Bench Pro Verified：清理泄漏与错误任务后的 Agent 基准

[论文](https://arxiv.org/abs/2609.08149)指出 SWE-Bench Pro 的金标准解答或隐藏评测信息泄漏会诱发 reward hacking，部分题目还存在误导性描述和测试范围错误；作者以 anti-hacking 隔离和最小化任务修正构建 Verified 版本，重新评测后发现若干前沿模型显著低于既有报告。**质量：B；证据成熟度：M1。** 数据与使用文档已公开，但仍需外部团队复跑并审计修订准则。**建议投入：了解即可（5～20 分钟）。** 优先读威胁模型、泄漏通道和任务修订原则；它能帮助你检查自己的 coding-agent benchmark 是否在无意中奖励“读答案”而非修复能力。

### Co-Evolving Harnesses and Models：完整模仿可能破坏模型—harness 匹配

[论文](https://arxiv.org/abs/2609.09134)在七类企业 Agent 任务上先为较弱模型演化 harness，再用更强模型提供监督；直接模仿专家完整轨迹让 Qwen3-Coder 和 Gemma 4 在全部七项上倒退 4～30 分。作者认为较弱模型会复制自己无法执行的专家规划风格，因此改为只定位其 on-policy rollout 的失败回合，并让专家重写该回合，从而保留原生规划方式。**质量：B；证据成熟度：M0。** 结果直接提醒“升级模型或微调权重”可能破坏既有正常 harness 链路，但目前缺少公开代码与第三方复现。**建议投入：了解即可（5～20 分钟）**，先读失败轨迹分析和局部纠错流程，等待资产发布后再投入复现。
