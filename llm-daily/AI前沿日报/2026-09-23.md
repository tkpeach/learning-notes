# 业界进展

### OpenAI 发布 GPT-6 Sol 与 GPT-6 Luna

[OpenAI 官方公告](https://community.openai.com/t/announcing-gpt-6-sol-and-gpt-6-luna/1399925)于 9 月 22 日宣布两款模型当天进入 ChatGPT Work 与 Codex，覆盖 Plus、Pro、Business、Enterprise 和 Edu；两者也进入 API，Free/Go 用户可在桌面端试用 Luna。官方把 Sol 定位为复杂编码与 Agent 工作流、Luna 定位为高吞吐低成本任务；[模型文档](https://developers.openai.com/api/docs/models)显示两者均为 1.05M 上下文、最大 128K 输出并支持函数、Web、文件搜索与 computer use，标准 API 标价分别为每百万输入/输出 token 2/10 美元与 0.1/0.5 美元。公告称相对 GPT-5.6 促销价降低 50%，并提高使用额度，但未给出 Codex 各订阅档的具体增幅。安全附录将两者按网络安全和生物/化学“High”能力部署、未达自我改进“High”，这些结论和性能图仍主要来自 OpenAI 自评。**重要性：高。**

### Anthropic 发布 Claude Opus 5.5

[Anthropic 官方发布](https://www.anthropic.com/claude-opus-5-5)于 9 月 22 日上线 `claude-opus-5-5`，覆盖 Claude 应用、Claude Code、API 与云平台。标准价格降至每百万输入/输出 token 4/20 美元，缓存读取降至 0.20 美元；官方称相对 Opus 5 典型任务成本降低约 40%，输出速度提高逾 30%，并提供最高 2.5 倍速的 Fast 模式。作者报告 FrontierCode 54.6%、CursorBench 52.5%，但跨厂商数字混用了不同 effort、harness 与各家自报成绩，不宜视作严格同条件排名。Anthropic 同时提高 Pro、Max、Team 的五小时使用上限并给订阅用户一次可储存的 rate-limit reset；这不是 Codex 额度变更。**重要性：高。**

### Qwen-Image-2.1 开源发布（补漏）

此前漏报，Qwen 于 9 月 20 日发布 [Qwen-Image-2.1](https://github.com/QwenLM/Qwen-Image-2.1)。官方仓库给出 7B 主模型、文本生图和单/多图编辑代码，可接受最多 10 张参考图，并支持原生透明图像；权重已进入 Hugging Face 与 ModelScope，Diffusers、ComfyUI、vLLM-Omni、SGLang 和 LightX2V 宣称 Day-0 支持。它把统一生成/编辑和多主体一致性压到可本地部署的开放权重规模，但仓库刚发布，官方展示与生态“支持”尚不能替代独立质量、显存和端到端速度复测。**重要性：高。**

## Part 2/3

# 系统与编译器进展

### vLLM 为硬件专用极速路径增加可移植的隔离层

[PyTorch/vLLM 联合技术说明](https://pytorch.org/blog/hardware-agnostic-models-in-vllm/)于 9 月 22 日解释，vLLM 的新 frontier “flat model”会用模型/硬件专用融合绕开 fullgraph `torch.compile`，但这会给旧 GPU、异构加速器和 out-of-tree 插件制造兼容断层。新 `model_executor/hw_agnostic` 路径把可编译、可覆写、与专用实现隔离、尽量用 PyTorch/Triton/Helion 可移植实现作为约束；Transformers backend 的有限层已可用 `USE_HW_AGNOSTIC=1` 启用，H100 上三个模型的总 token 吞吐几何平均距原生实现在 3.4% 内。关键价值是明确把“前沿硬件峰值”和“生态可移植性”分成两条实现链；但 flat model 对应实现、CI 与 DeepSeek V4 支持仍在落地或评审中。建议投入：**立即学习（1～3 小时）**，重点读层覆写边界和双路径维护成本。

### Transformers 直接运行 llama.cpp GGUF 量化权重

[Hugging Face 官方文章](https://huggingface.co/blog/transformers-llama-cpp-quants)于 9 月 22 日宣布，在 Apple Silicon 上可经 `from_pretrained(..., gguf_file=...)` 保持 GGUF packed 权重，并通过 `kernels` 复用 ggml 的量化矩阵、归一化、注意力和 gated-delta-net Metal kernel；`transformers serve` 还能直接暴露 OpenAI 兼容接口。生成循环同时移除不必要 attention mask 检查、延后一拍读取 stopping 条件，减少 CPU/GPU 同步。作者称 Qwen3.5/3.8 的三组 warmed 测量接近 llama.cpp，但对照一列包含 prefill、另一列是 decode-only，不能按柱状图直接判定等速；当前 packed 路径仅 MPS、batch/padding 尚不完善、架构覆盖有限。建议投入：**立即学习（1～3 小时）**，适合需要在 PyTorch 中检查激活、评测量化误差或试验解码逻辑的本地推理工作流。

### UK AISI 用 Evaluation Cards 公开可复核评测配置

[Hugging Face、EvalEval 与 UK AISI 的发布](https://huggingface.co/blog/evaleval-aisi)把 HealthBench、FrontierMath、HLE、SWE-Bench Pro、Terminal-Bench 2.0 及两项网络安全评测的结果、上下文和配置信息整理为 Evaluation Cards，并采用 Every Eval Ever 共享 schema。其价值不是又一张排行榜，而是让同名 benchmark 在推理预算、oracle 反馈和协议差异下可被追踪；文章也展示 HLE 随 token 预算和反馈机制变化的累计成功曲线。当前公开范围仍是 AISI 选择的结果，不能自动解决任务污染、judge 误差或跨机构复跑成本。建议投入：**了解即可（5～20 分钟）**，做模型评测时可把 schema 当作报告最小字段清单。

### [InternScience/ScienceIDE](https://github.com/InternScience/ScienceIDE)：科学代码环境开始从论文附件变成可执行训练资产

**质量：B；证据成熟度：M1；个人价值：高。** 仓库已公开 15/64 个环境、30/85 个高难任务、SFT/RL 代码、执行验证器，以及 4B/9B/72B 的 PhAI-IDE 模型；[项目页](https://internscience.github.io/ScienceIDE/)进一步列出 64 个环境、27 个代码库和 2,812 个任务的完整规划。现有资产已足以审查任务目录、环境构建和验收逻辑。限制同样明确：任务库仍未全量开放，模型增益在不同 benchmark 上并不一致，部分 HumanEvalFix 结果甚至下降，且尚无第三方科学软件复跑。**建议投入：立即学习（1～3 小时）**，先复跑一个公开环境并审计验收条件；现在值得看，是因为它把 AI for Science 的口号落成了可执行、可验证的数据生产链。

# 科研进展

### Harness-Zero：把专用 Agent harness 的行为蒸馏进模型权重

[论文](https://arxiv.org/abs/2609.24974)提出让一个“harnessing agent”在训练 rollout 执行前审阅并改写 student 响应，再只把目标 harness 动作空间内的接受轨迹用于 SFT，使部署时可以移除专用 harness。作者在 SpreadsheetBench、AppWorld 与 USPTO 三域上报告 Qwen3.5-9B 的宏平均成功率由 23.3% 提升至 44.3%，并高于挂载优化 harness 的基线 41.7%；28 类 harness 独有行为平均恢复 82.3%。[作者仓库](https://github.com/metaevo-ai/harness-zero)已公开三域任务集、harness bank、rollout/SFT 代码、Docker 路径与 LoRA checkpoints。**质量：B；成熟度：M1；个人价值：高。** 风险在于训练、教师调用和 harness 演化成本尚未与更简单的蒸馏基线充分拆开，三域结果均由作者团队给出，且行为“进入权重”可能同时带来更新困难和分布外脆弱性。建议**了解即可（5～20 分钟）**，待独立复跑和跨模型消融后再投入训练资源。

# 本期最值得关注

1. **GPT-6 Sol/Luna 与 Opus 5.5 的能力—成本分层。** 两家都把新模型直接放进编码 Agent 产品并下调单位成本，但 benchmark 口径不可直接横比。先按自己的任务、effort、工具链和总 token 成本做小样本 A/B，而不是按单一榜单迁移。
2. **vLLM 的“专用极速实现 + 硬件无关实现”双路径。** 这是模型架构快速分化后很现实的维护答案。建议花 1～3 小时核对 `hw_agnostic` 层、Transformers rewiring 与插件覆写点，判断自用加速器会落在哪条链路。
3. **Harness-Zero 的训练时 harness 蒸馏。** 方法把外部脚手架能力转成权重内行为，方向新颖且资产较完整；现阶段更适合复核轨迹和 baseline，而不是直接采信 23.3%→44.3% 的跨域外推。
