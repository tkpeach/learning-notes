# 业界进展

### Claude 将 Cowork 与聊天统一为可跨设备继续的工作流

Anthropic 于 9 月 16 日发布 [Claude Cowork and chat are now one Claude](https://claude.com/blog/cowork-is-now-claude)：将原来偏桌面的 Cowork 与对话界面合并，任务上下文可在网页、桌面和移动端衔接，并推出测试版 Claude Docs、Claude Slides 与定时任务。默认仍要求用户批准实际动作。Pro/Max 将在数周内陆续获得，Team/Free 后续开放，Enterprise 至少提前 30 天通知。这是 Agent 产品交互与分发的整合，尚不能等同于底层模型能力更新。**重要性：中。建议投入：了解即可（30～60 分钟）。**

### OpenAI 同日推进广告 Agent 与工作方式研究

[Reimagining advertising with AI](https://openai.com/index/reimagining-advertising-with-ai/) 描述了面向部分美国广告主测试的 Sponsored Agents：用户可主动进入赞助对话，且与 ChatGPT 原本独立生成的回答区分。OpenAI 还在 ChatGPT Work 中提供 Ads Manager 插件，用于广告活动与素材工作流，并接入 HubSpot、Shopify。产品仍处测试阶段，广告与普通回答的边界及效果需要在真实使用中继续观察。**重要性：中。建议投入：了解即可（30～60 分钟）。**

OpenAI 的[工作方式研究](https://openai.com/index/unlocking-new-ways-of-working/)基于 2026 年 4～7 月逾 150 万条工作相关 ChatGPT 消息和约 6200 名持续可观察用户，报告跨职业任务占比从 13.1% 升至 25.9%、重复进入工作流的比例为 23.6% 对 8.4%。这是观察性用户样本，不能据此推断全体劳动者的因果生产率收益。另一篇[老年人 AI 使用项目](https://openai.com/index/helping-older-adults-use-ai-in-everyday-life/)介绍与 OATS/AARP 合作、在美国 10 座城市面向约 1000 名老年人开展工作坊，属普及与培训进展。**建议投入：了解即可。**

# 系统与编译器进展

### NVIDIA 用共享 Tile IR 和机器可检验闸门组织 Agent 迁移 GPU kernel

**重要性：高。** NVIDIA 9 月 16 日公开[从 cuTile Python / Triton-TileIR 迁移至 cuTile Rust 的完整流程](https://developer.nvidia.com/blog/translating-cuda-tile-operations-from-python-to-rust-using-agentic-ai/)。三种前端汇入同一 `cuda_tile` 方言，Agent 先提取参考 kernel 的 shape、dtype、启动参数与 Tile IR，再由分工明确的阶段生成 Rust kernel、FFI 包装和测试；每阶段以固定 schema、退出码和 `VERDICT` 路由，失败重试次数有硬上限。关键设计是先做 IR 结构对比，再做数值正确性和性能检验，防止“样例测试通过但内存操作、掩码或 reduction 轴已经偏离”的伪迁移。

官方将 TileGym 的 24 个公开算子、约 40 个 kernel 迁移至 Rust。在 B200 上对 347 组配对配置以 CUPTI 设备时间测得总体几何平均性能比 0.995，所有算子达到至少 0.95 的门槛。不过这不是端到端应用延迟；部分迁移仍需不安全 API 才能匹配原 IR，且验证环境依赖 CUDA 13.1+、Blackwell、Rust 1.89+ 与 `tileiras`。对编译器和 Agent 工程最可借鉴的是将中间表示、可复现测试和有界状态机用作主路径，而非只评估生成代码能否编译。**建议投入：深入学习（半天以上）。**

### vLLM 为 Kimi K3 补上推测解码训练与服务层优化细节

**此前漏项。** vLLM 9 月 15 日披露[在 GB300 NVL72 上训练 Kimi K3 的 DSpark draft 模型](https://vllm.ai/blog/2026-09-15-kimi-k3-dspark)：约 5B 参数的 draft 一次预测 8 个 token，平均接受长度 4.11；官方在数学负载中报告单用户生成速率约从 110 升至 435 token/s，在匹配交互延迟下最高约 3.5 倍输出吞吐。技术关键是跨节点提取 target hidden state、借 Mooncake connector 连接训练与推理，并公开 draft checkpoint 和 Speculators 工具。数字来自特定 K3、GB300 和 workload，不应外推到其他模型或并发条件。

配套的[9 月 13 日服务优化回顾](https://vllm.ai/blog/2026-09-13-kimi-k3-performance-optimization)涵盖调度、KDA 前缀缓存、ReplaySSM 状态恢复、prefill/decode 解耦与 GPU kernel 的连续优化，官方概括吞吐提升 2.8 倍。两篇共同说明，推测解码收益依赖隐藏状态数据路径和既有 serving 栈，而不只是 draft 模型本身。**建议投入：立即学习（1～3 小时）。**

vLLM 与 Novita AI 同日还公开 [Chord W4A16 MoE kernel](https://vllm.ai/blog/2026-09-15-novita-chord-w4a16-moe)，为 Kimi K2.x 的 INT4 权重、BF16 激活提供按每专家 token 数选择的 indexed 与 grouped 两类路径。H200 对已调优 Humming 的逐层测量约快 1.1～1.3 倍；B300 最高 2.15 倍对比的是**未调优** Humming 默认配置，不宜直接当作同等优化水平的优势。更接近实际服务的 8×H200 ShareGPT 测试中，TTFT 降 8.6%、输出吞吐提升约 4%～8%；grouped 路径接入 vLLM 仍在进行中。**建议投入：了解即可（30～60 分钟）。**

# GitHub 高价值项目洞察

[NVIDIA/TileGym](https://github.com/NVIDIA/TileGym)随上述技术文章提供转换 Agent 的 Skill、阶段校验脚本、示例和 24 个 Rust 算子实现。它值得作为“IR 结构校验 + 端到端正确性 + 独立性能门槛”的工程样本；但实践门槛是 Blackwell/CUDA 13.1，且目前性能证据主要来自 NVIDIA 自身 CI，不宜据此认定可跨硬件复用。**建议投入：立即学习（1～3 小时），先读转换协议与校验器，再选小算子复跑。**
