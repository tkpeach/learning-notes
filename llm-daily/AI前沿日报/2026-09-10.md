# 业界进展

### OpenAI 公布 Navier–Stokes 有限时间奇性证明与 Lean 形式化

**重要性：高。** OpenAI 公布了一份 166 页证明，声称对受迫三维不可压 Navier–Stokes 方程的两类表述构造出有限时间奇性，并同步开放 [Lean 形式化仓库](https://github.com/openai/NavierStokesAndEuler)。官方称发现阶段使用了一个“显著强于 GPT-6 Astra”的内部模型，约 10,000 个并发 Agent 运行 88 小时后得到结果；随后用 GPT-6 Astra 完成额外约 17 小时的形式化与验证。Navier–Stokes 单项累计约 270 万条消息、1,300 亿输出 token，显示前沿 AI Scientist 工作流已从单次对话扩展到大规模并行搜索与形式化校验。[官方说明](https://openai.com/index/navier-stokes-solution/)｜[论文](https://cdn.openai.com/pdf/32d9f210-8b73-45e0-91bc-82a30aef8a9a/navier-stokes.pdf)

必须把“机器可检查”与“数学界已接受”分开：Lean 只能验证已编码定义和证明项的内部一致性，不能自动保证形式化陈述完整对应千禧年问题的预期含义；OpenAI 也没有宣称已经获得千禧年大奖。当前结论仍来自项目方，需等待流体力学专家、Lean 社区和克雷数学研究所流程的独立审查。

### OpenAI 发布 ChatGPT Images 2.5

**重要性：高。** Images 2.5 主打更清晰的细节、更精确的多轮编辑和参考主体保持，官方称相较 Images 2.0 最多降低 50% 生成延迟；它已覆盖 ChatGPT、Work 与 Codex 各端。API 同步提供默认的 GPT-Image-2.5 Flare 和控制更强、速度更慢的 Sunburst，并继续加入 C2PA 凭证与不可见水印。性能与主体一致性数据目前主要来自官方，需要用真实编辑工作流复核。[官方发布](https://openai.com/index/introducing-chatgpt-images-2-5/)

### GPT-5.6 Sol 开始进入量子实验测量闭环

**重要性：中。** MIT EQuS 的研究者把 GPT-5.6 Sol 通过 Codex 和实验室软件连接，在一块未校准的六量子比特超导芯片上，让 Agent 选择参数、执行测量、分析结果并保存校准。官方案例显示，标准测量序列可在较少干预下完成，而弱信号和高噪声情形仍更慢并需要专家指导。它证明的是边界清晰、工具受控的实验自动化价值，不等同于模型已经能够自主设计和验证开放式物理实验。[官方案例](https://openai.com/index/codex-quantum-computing-experiments/)

# 系统与编译器进展

### Claude Platform：先修缓存与陈旧提示，再调高推理强度

**重要性：高。** Claude 的新工程指南把成本优化拆成三个可执行层次：提高 prompt cache 命中率、清除陈旧 prompt 反模式、按任务校准 effort。缓存层最容易被忽略的是前缀必须逐字节相同、模型版本需固定、默认 TTL 只有五分钟，以及工具定义或长时间子 Agent 调用会破坏缓存连续性。`/claude-api prompt-audit` 的示例在客服 benchmark 中移除六种遗留反模式后，平均成本下降 14.6%、准确率提高 5.3%；`hillclimb` 在 14 个留出样本上从 78.6% 提升到 90.5%，成本约为原来的五分之一。官方还给出 LegalBench、tau2 retail、OfficeQA Pro、SWE-bench Verified 等任务 52%～73% 的成本下降案例，但这些仍是特定评测与官方自报结果，不能直接外推到生产负载。[官方技术文章](https://claude.com/blog/reducing-cost-and-improving-performance-with-claude-platform)

**建议投入：立即学习（1～3 小时）。** 选一个现有 Agent 请求链，先记录 cache hit、输入 token、effort 和任务成功率，再依次做前缀稳定化、prompt audit 与 effort sweep。学完后可以把“模型变便宜”拆成缓存、上下文卫生和推理预算三类独立杠杆，并建立可回归的成本—质量实验，而不是只靠换模型或缩短提示词。

# GitHub 高价值项目洞察

### openai/NavierStokesAndEuler：可独立检查的 Lean 证明资产

[官方仓库](https://github.com/openai/NavierStokesAndEuler)提供 Lean 4.34.0-rc2 工程，按 `NavierStokes`、`Euler` 与 `ComparatorChallenges` 组织形式化内容，并给出通过 Mathlib 缓存和 `lake build` 独立检查的路径。仓库只有一次公开提交，不能用提交数衡量证明质量；真正有价值的是它把自然语言数学主张落到了可由 proof kernel 检查的对象上，也让外部研究者可以逐项核对定义、假设和定理边界。

**质量：B；证据成熟度：M1。** 核心证明代码和论文均已公开，但缺少独立数学审查，且“形式化无错误”不自动推出“准确形式化了目标问题”。**建议投入：立即学习（1～3 小时）**，先运行完整构建，再从主定理追踪到强迫项、光滑性和爆破解释的定义；可以跳过大规模 Agent 统计，优先寻找自然语言论文与 Lean 陈述之间的语义缝隙。学完后能更具体地判断形式化验证在 AI 数学发现链路中能保证什么、不能保证什么。

### radixark/miles：覆盖 rollout、训练与权重同步的后训练栈

[Miles 仓库](https://github.com/radixark/miles)不是论文壳项目：它有超过两千次提交，包含训练入口、异步执行、SGLang rollout、Megatron-LM 与 PyTorch FSDP trainer、三种权重同步方式，以及 RL、LoRA RL、on-policy distillation、SFT 和 diffusion 等路径。v0.1 技术报告给出的代表性案例是在 64 台 GB300 上对 GLM-5.2 744B-A40B 做全异步 terminal-coding RL，前 30 步中位 step time 为 263 秒。[论文](https://arxiv.org/abs/2609.08368)

**质量：B；证据成熟度：M1。** 工程资产和超大规模案例都很强，但关键性能结论仍主要由作者提供，安装复杂度、故障恢复和跨集群复现尚未得到独立验证。**建议投入：立即学习（1～3 小时）。** 从 `train.py` 追踪 rollout—trainer—weight sync 数据流，再选择小模型跑同步与异步各一条最小 recipe；不要从 744B 案例起步。学完后可以建立大规模后训练系统的控制面与数据面心智模型，并能判断不同并行训练后端和权重同步策略的适用边界。

# 科研进展

### BeaconKV：用“灯塔查询”保留可能被远距离重访的 KV

BeaconKV 提出一种无需训练的 KV-cache 压缩方法：生成少量代表性 beacon query，估计历史 token 在未来被远距离查询时的重要性，再据此保留缓存。作者在四个开放推理模型的数学、科学和代码任务上报告最高 5.8× 显存压缩、超过 4.3× 吞吐提升，并称准确率接近完整 KV；[代码仓库](https://github.com/aiha-lab/BeaconKV)已提供 Qwen3 与 DeepSeek-R1-Distill 的实现和评测脚本。[论文](https://arxiv.org/abs/2609.04971)

**质量：B；证据成熟度：M1。** 方法直接针对长推理中的“早期信息被稍后重访”问题，且已有核心代码；但仓库目前只有少量提交，结果仍缺少第三方复现，吞吐收益也可能高度依赖 batch、序列结构、FlashAttention 版本和硬件。**建议投入：了解即可（5～20 分钟）。** 先读重要性估计与 eviction 规则，等待端到端 serving 集成和独立长上下文复现后再投入实现。

# 本期最值得关注

1. **Navier–Stokes 证明与 Lean 仓库。** 它把大规模多 Agent 搜索、数学发现和机器形式化串成了一条可外部检查的链路；即使最终结论需要修正，这套“声明—形式化—语义审查”框架仍值得掌握。建议投入 1～3 小时，从主定理和假设映射入手，而不是先读 166 页全文。
