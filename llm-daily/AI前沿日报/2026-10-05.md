## Part 3/3

# 科研进展

### Harness-Zero：把专用 Agent harness 的行为蒸馏进 9B 模型（9 月 21 日论文复评）

**质量：A｜重要性：高｜Evidence Maturity：M1｜Personal Utility：极高。** [论文](https://arxiv.org/abs/2609.24974)要解决的不是通常的“模仿强模型答案”，而是专用 harness 提供的工具、记忆、技能和中间件如何在部署时被移除，却让弱模型保留其收益。作者先针对任务域优化一套 harness，再把其中可迁移的规则整理成审阅依据。训练采样时，学生始终运行在只有一个 Bash 工具的固定目标 harness 中；一个较强的审阅 Agent 在学生每次响应执行前决定通过或改写，改写也必须符合学生自己的动作空间。只有最终被接受的响应和工具观察进入学生轨迹，审阅者的私有讨论不进入训练数据。随后做 SFT，推理时不再加载专用 harness 或审阅 Agent。[官方仓库](https://github.com/metaevo-ai/harness-zero)公开三域任务、harness bank、Harbor/Docker 环境、轨迹与训练代码、测试及三个按领域分别训练的 LoRA 检查点，具备实际复查路径。

**结果为什么值得重视。** 在 SpreadsheetBench、AppWorld 和 USPTO 逆合成上，同一个 Qwen3.5-9B 底座、按三域等权平均，固定简易 harness 下的成功率由 **23.3% 升至 44.3%**；不训练而挂载优化 harness 的底座为 41.7%。但三个检查点是**各领域分别训练**，44.3% 不能解读为一个通用模型同时覆盖三域。更有辨识度的是 USPTO 消融：直接用强教师轨迹微调仍为 12%，让教师带专用 harness 生成轨迹降至 3%，仅给审阅者任务答案为 15%，而提供 harness 规则、逐步审阅学生当前行动得到 30%。这说明高成功率的示范轨迹不一定是有效监督；动作空间一致、贴近学生当前状态的纠错可能更重要。作者还比较强模型直接运行时的 agent-as-harness 与代码式 harness，六组平均 81.1% 对 78.1%，但不能把这 3 个百分点与 9B 模型蒸馏结果混成同一实验。

**边界与下一步。** 上述均为作者自测，尚缺独立复跑或跨基座验证。USPTO 上蒸馏模型虽从 12% 升到 30%，仍低于挂载专用 harness 的 38%，提示程序性检查比领域知识与可执行验证器更容易吸收入权重。方法依赖强审阅模型；作者报告较弱审阅者可能带来负收益，而且逐步多一次模型调用使 USPTO 轨迹收集平均耗时约为原来的 2.4 倍，这笔成本只是转移到训练期。还需检验 harness 更新后是否要重新蒸馏，以及分布外任务中已学行为是否稳定。**建议投入：深入学习（半天～2 天）；先读动作空间转换和 USPTO 消融，再选一个小任务用公开脚本核对轨迹过滤、训练成本与部署后效果。**
