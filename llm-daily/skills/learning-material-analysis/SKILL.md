# 学习资料分析与知识沉淀

## 目标

帮助用户判断一份资料：

- 实际说了什么，以及哪些内容只是作者或整理者的解释；
- 与已有方法、常规做法或用户已有知识相比真正不同在哪里；
- 结论由什么证据支持，是否存在未验证的假设、疑问和反例；
- 是否值得复现、应用、继续检索或加入长期知识库。

不要把资料改写成只有摘要的内容，也不要因为多个分析方向得出相似结论就把它当成事实。

## 资料类型路由

先判断主要资料类型，再选择分析重点。混合资料可以拆成多个单元分别处理。

- **论文**：重建问题、方法、假设、实验、创新性、基线公平性和复现价值。
- **书籍或章节**：提炼概念体系、知识依赖、解释框架、共识与作者观点。
- **新闻**：核验事件、来源、发布时间与事件发生时间，区分已确认事实、来源声称和影响推断。
- **日报或 Daily 日志**：去重、聚类、连接已有知识，提炼值得跟进的线索和行动。
- **Prompt 实践建议**：提取可复现做法、适用条件、失败边界，并把未经验证的经验转为实验假设。
- **教程或博客**：提炼操作路径、版本和依赖、隐含前提，以及是否有足够失败信息。

详细分析协议见 [references/analysis-protocol.md](references/analysis-protocol.md)。子 agent 的专家角色卡和启动要求见 [references/agent-roles.md](references/agent-roles.md)。需要稳定的输出结构或写入知识库时，使用 [references/output-template.md](references/output-template.md)。

## 独立多视角分析

优先让不同角色在互不可见的情况下独立分析同一份原始资料，然后再汇总冲突。若当前环境不能真正并行或隔离 agent，则在同一上下文中依次完成独立分析：每个角色开始前不得阅读其他角色的结论，不得根据多数意见替代证据判断。

每次分析都必须区分以下执行状态，并在最终报告中披露：

- **真实独立 agent**：多个 agent 实际独立运行，彼此不可见；
- **单 agent 独立轮次**：同一 agent 按角色依次分析，期间不读取其他角色结论；
- **单 agent 综合判断**：未完成独立角色分析，仅进行一次综合分析。

不得把“按多个角色思考”表述为“多个 agent 达成共识”。

至少覆盖 [references/agent-roles.md](references/agent-roles.md) 中的事实重建者、作者立场分析者和反方审查者，并根据资料类型选择一个专门角色。启动子 agent 时，必须传入对应角色卡中的完整“身份与任务”部分，而不能只传递角色名称。

默认最多使用四个角色：事实重建者、作者立场分析者、反方审查者，以及一个与资料类型最相关的专门角色。只有在资料争议较大、用户要求深入分析或结论会影响重要决策时，才增加其他角色。每个子 agent 只负责自己的专家任务，不负责生成总报告，也不能读取其他子 agent 的结果。

按资料类型选择专门角色：

- 新闻或日报：来源与时效性分析者、事实核验者；
- Prompt 或教程：复现与实验设计者、实现成本分析者；
- 书籍：知识结构分析者、概念边界分析者。

除作者立场分析者外，其他角色不能默认替作者补充动机或替作者辩护。

## 受控二次讨论

主 agent 汇总各角色的差异，而不是先平均或投票。只挑选真正影响结论的冲突点进入第二轮，使用如下问题质询相关角色：

- 该主张的原文或数据证据在哪里？
- 这是事实、资料内结论、个人经验、合理推断还是待验证假设？
- 哪个前提改变后，结论会失效？
- 是否存在简单替代方法、反例或相反证据？
- 需要什么最小实验或外部来源才能区分不同解释？

二次讨论不能制造资料中不存在的证据。无法解决的分歧应保留在最终报告中。

每个进入最终报告的重要争议，都必须按以下链路展开：

```text
初始主张 → 反方质疑 → 关键证据 → 回应或无法回应 → 当前裁决 → 对最终结论的影响
```

不能只写“存在局限”“需要进一步验证”等没有推理过程的结论。如果没有重大分歧，应明确写出“未发现会改变最终判断的重大分歧”，不要重复展示相同意见。

## 证据与不确定性规则

每一个重要判断都要尽量绑定原文位置、图表、公式、实验结果、来源链接或日志中的具体例子。明确区分：

- **已确认事实**：由原始资料或可靠一手来源直接支持；
- **资料内结论**：资料作者报告的结果，只在其设定下成立；
- **合理推断**：根据证据推导，但没有直接验证；
- **个人经验**：日志、博客或实践者的观察；
- **待验证假设**：有理由尝试，但证据不足；
- **有条件或可能过时的结论**：依赖模型、软件版本、时间、数据分布或其他环境条件。

最终报告必须同时给出不确定点、疑问、潜在反例和没有被资料回答的问题。不要用“多个 agent 同意”作为事实依据。

新闻必须特别记录来源类型、事件时间、报道时间和当前时效性。Prompt 建议必须记录适用模型、任务、输入条件、指标或缺失的验证信息；没有对照实验时，不得表述为普遍有效。

## 输出模式与复杂度控制

默认采用“摘要优先、讨论适度展开”模式：

1. 先用三至五句话给出核心判断；
2. 再列出最值得记住的关键点；
3. 用表格展示重要主张、证据、状态和可信度；
4. 只展开两至三个会改变最终判断的争议；
5. 最后给出行动建议和执行状态。

除非用户要求“详细展开”“逐角色分析”或“展示完整讨论过程”，否则不要完整展示每个角色的全部分析记录，也不要为了覆盖模板而重复内容。

## 输出要求

默认输出以下内容，按资料类型调整标题措辞，并遵守“摘要优先、讨论适度展开”模式：

1. 一句话判断；
2. 资料讲了什么；
3. 最值得记住的关键点；
4. 与已有方法或一般做法的差异；
5. 证据与可信度；
6. 不确定点、疑问和反例；
7. 适用场景、潜在价值和限制；
8. 建议的下一步：继续检索、最小复现、A/B 实验、加入工作流或暂不跟进；
9. 关键讨论过程：使用“主张 → 质疑 → 证据 → 回应或无法回应 → 裁决”的结构，只保留改变最终判断的分歧。
10. 执行状态：说明使用了真实独立 agent、单 agent 独立轮次，还是单 agent 综合判断。

如果用户要求沉淀到仓库，优先写成结构化知识卡片，并保留结论状态、来源、日期、关联主题和待验证事项。未经验证的经验进入“待验证区”，不要直接写成长期事实。

## 边界

不要擅自把新闻扫描、外部检索、代码实现或知识库写入当作默认动作。只有用户要求或任务明确需要时才执行；需要外部检索时说明检索范围和时间边界。不要改写已有日报的固定结构，除非用户明确要求。
