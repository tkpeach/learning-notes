# 分析协议

## 第一阶段：资料拆分

将输入拆成可独立判断的主张、方法、事件、建议或概念。为每个单元记录：

- 来源和标题；
- 资料类型；
- 日期、版本或上下文；
- 原文位置或可定位的例子；
- 需要回答的核心问题。

混合日报可以按条目拆分。不要把同一日报中的所有内容强行归纳为一个结论。

## 第二阶段：独立分析记录

启动角色时，读取 [agent-roles.md](agent-roles.md) 中对应的角色卡，并将原始资料、用户问题、资料类型和角色卡一起传入。不要用“请从某某角度分析”这种单句描述替代角色卡。

每个角色分别回答：

```text
主张：
证据：
推理：
结论状态：已确认事实 / 资料内结论 / 合理推断 / 个人经验 / 待验证假设 / 可能过时
置信度：高 / 中 / 低
不确定点：
疑问：
潜在反例：
```

事实重建者不得添加评价；作者立场分析者不得把推断伪装成原文；反方审查者也必须提供具体理由，不能只提出抽象怀疑。

记录实际执行方式：真实独立 agent、单 agent 独立轮次，或单 agent 综合判断。只有第一种方式可以描述为多个 agent 的独立意见；第二种方式应说明是同一 agent 的隔离分析轮次；第三种方式不得声称完成了独立多视角分析。

## 第三阶段：按类型追加检查

### 新闻与日报

检查原始来源、报道时间、事件发生时间、是否为一手信息、是否存在多家独立来源、标题与正文是否一致。将“影响”拆为直接影响、合理推断和待观察影响。

### Prompt 与实践建议

检查模型、版本、任务、数据、提示词完整性、输出评价方法、成本和失败案例。若信息不足，提出最小 A/B 实验，而不是替作者推广结论。

### 论文

检查问题定义、关键假设、方法差异、基线、数据集、消融、统计显著性、计算成本、限制和复现信息。严格区分论文声称的贡献与分析者判断的贡献。

### 书籍与教程

检查概念间依赖、适用范围、简化之处、版本依赖和与已知方法的连接。对于争议性观点，标记为作者观点或学派观点。

## 第四阶段：冲突矩阵

主 agent 只将影响最终判断的冲突放入矩阵：

| 议题 | 支持判断 | 反对判断 | 关键证据 | 尚缺什么 | 当前裁决 |
|---|---|---|---|---|---|

当前裁决可以是“支持”“部分支持”“无法判断”或“资料不足”。不要用简单多数取代证据。

从冲突矩阵中只选择会改变最终结论或行动建议的议题，使用以下格式展开：

```text
争议：[议题]
初始主张：[角色或资料提出的判断]
反方质疑：[具体质疑]
关键证据：[原文位置、数据、来源或缺失证据]
回应：[可以回应的部分；不能回应的部分]
当前裁决：[支持 / 部分支持 / 无法判断 / 资料不足]
影响：[对最终结论或行动建议的影响]
```

如果没有达到这个重要性标准的冲突，只说明未发现重大分歧，不展开虚构的辩论。

## 第五阶段：行动判断

按照收益、成本、证据强度和可逆性判断下一步：

- 低成本且可逆：建议快速尝试；
- 证据不足但潜在收益高：建议先做最小验证；
- 成本高且结论不稳：先补充检索或暂不跟进；
- 仅有新闻价值：记录影响和观察指标，不强行转成技术行动。
