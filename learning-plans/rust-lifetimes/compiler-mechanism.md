# 深入：生命周期关联、编译器约束与代码生成

本页回应学习者关于“关联是什么操作、运行时做什么、是否像模板生成多份代码”的问题。它是学习内容；首次判断及纠正保存在过程记录。

## 1. 关联是类型契约，不是执行操作

```rust
fn first<'a>(x: &'a str, y: &str) -> &'a str { x }
```

输入 x 和输出都出现 'a，表示两者共享一个有效性参数。编译器使用它检查引用使用是否合法；不会向 x 或返回引用写入一个名为 'a 的运行时字段，也不会建立一张运行时依赖表。

这也不是把返回引用的地址与某个参数地址做等值绑定。返回的可以是 x 的一个子切片；类型契约要求的是它的有效性满足 'a，而非指针与 x 完全相同。

从本课共享引用的调用点看，可以用一个简化约束模型理解：

```text
U：输出被使用所需的范围
R：本次调用推断出的 'a
X：x 的数据能支持这次共享借用的范围

U ⊆ R ⊆ X
```

若 y 也标为 &'a str，则再加一条 R ⊆ Y。实际 region 不只是源码行号区间，还涉及控制流与函数外的有效性关系；这个模型用来理解本课直线代码，不是 rustc 全部内部算法。

## 2. 用约束解释练习中的 B

```rust
fn first<'a>(x: &'a str, y: &'a str) -> &'a str { x }
```

内层 inside 销毁之后还要读取 r，则 U 包含外层打印。R 必须覆盖这次读取，但同时又要由 inside 的借用有效性支持，二者不能同时满足。函数体返回 x 不会取消签名中已经存在的 y 约束。

把打印移进内层块后，U 不再包含 inside 销毁后的读取，可以找到同时由 outside 和 inside 支持的 R，因此通过。注意这并不是“返回值总是只与 outside 关联”，而是两个输入的约束此时都能满足。

## 3. 编译器做什么

rustc 的借用检查工作在 MIR（中层中间表示）上。简化流程为：

1. 把函数体中的控制流、借用、移动和使用表示出来。
2. 给需要推断的生命周期建立 region 推断变量。
3. 根据引用使用、类型和签名关系收集有效性与 outlives 约束。
4. 传播并求解约束，检查引用有效性及借用冲突；无法满足时报告错误。

函数实现检查与调用检查有不同视角：实现只能依赖签名给出的关系来证明返回值合法；调用点则必须让实际参数与结果使用满足这些关系。编译器确实检查函数体，但不会为一个调用者根据函数体收窄公开签名的依赖。

来源：[MIR 借用检查](https://rustc-dev-guide.rust-lang.org/borrow-check.html)、[Region inference](https://rustc-dev-guide.rust-lang.org/borrow-check/region-inference.html)。核查日期：2026-10-20。

## 4. 运行时做什么

普通引用的生命周期参数不作为运行时参数传递，不产生生命周期计时器、引用计数或逐次访问的生命周期检查。编译期检查完成后，region 信息在后续代码生成相关阶段被擦除；运行时仍执行函数自身的读取、返回、分支等操作。

String 的释放仍按所有权语义发生。生命周期标注不会把它推迟到某个引用最后一次读取之后；若读取晚于数据失效，编译器应拒绝程序。

来源：[rustc 类型表示与 region 擦除](https://rustc-dev-guide.rust-lang.org/ty.html)。擦除的是生成运行代码不再需要的生命周期参数，不代表函数契约在编译期无效。

## 5. 为什么声明 <'a>，与模板有什么关系

`<'a>` 声明一个生命周期泛型参数，使签名中的 'a 成为受这个函数绑定的名字。类似 `fn id<T>(x: T) -> T` 需要声明 T；它不是给引用起一个全局标签。对这个例子，改名为 'text 并在相关位置一致替换，不改变关系。

函数实现必须适用于满足声明约束的调用，不能假定传进来的所有数据都永久有效。调用处通常让编译器推断生命周期参数，无需手写一个具体时间范围。

Rust 泛型参数包含生命周期、类型和 const 参数，但代码生成方式不能一概而论：

| 参数 | 用途 | 是否因参数不同产生代码实例 |
| --- | --- | --- |
| 'a | 引用有效性关系 | 不会仅因生命周期不同产生不同机器码实现 |
| T | 具体数据类型、操作与布局等 | rustc 按需要对具体类型单态化；优化后可能内联、合并或消除 |
| const N | 编译期常量 | 可以参与实例化、布局与代码生成；本次不展开 |

`fn id<'a, T>(x: &'a T) -> &'a T { x }` 同时包含两种泛型：类型差异可参与单态化；同一类型的长、短借用不会仅因生命周期不同而生成独立实现。不能据此保证最终二进制里恰好保留某个数量的函数，因为还有内联等优化。

来源：[Rust Reference：泛型参数](https://doc.rust-lang.org/reference/items/generics.html)、[单态化](https://rustc-dev-guide.rust-lang.org/backend/monomorph.html)、[region 擦除](https://rustc-dev-guide.rust-lang.org/ty.html)。

## 8. 覆盖方向从哪里来

本节针对直接的共享引用 &str。'a 是一个参数名，不自带“覆盖别人”或“被别人覆盖”的角色。编译器根据类型检查中的来源/目标关系、引用使用位置及显式约束，产生有方向的要求。

### 8.1 基本规则：已有保证须覆盖目标要求

若一个表达式的类型是 &'source str，而当前位置要求 &'target str，则需满足 'source: 'target，即 source 至少覆盖 target。可以把较长的有效性保证缩短使用，不能无依据地延长它。

```rust
fn forward<'src: 'out, 'out>(x: &'src str) -> &'out str {
    x
}
```

返回表达式 x 提供 src，返回类型要求 out，因此方向是 src 覆盖 out。删除 'src: 'out 后，函数实现不能对任意独立的 src/out 保证安全，实际编译失败并提示添加这个方向的约束；加上后编译及运行断言通过。

如果输入与输出都用同一个 'a，那么函数体返回 x 时，相当于用 a 满足 a，自然成立。并不是编译器规定“输入永远比输出长”；例如函数若返回字符串字面量，来源保证是 static，可以独立于输入满足输出要求。

### 8.2 同一个参数在不同边界的角色

设签名为 `fn first<'a>(x: &'a str) -> &'a str`，在一次调用中把 a 记为 R：

| 检查位置 | 来源提供什么 | 目标/使用需要什么 | 导出的方向 |
| --- | --- | --- | --- |
| 调用时传入实参 | 实参引用可支持的有效范围 X | 形参 &'a str 要求 R | X 覆盖 R |
| 函数体返回 x | x 提供 R | 返回类型要求 R | R 覆盖 R |
| 调用者读取返回值 | 返回类型提供 R | 后续读取需要 U | R 覆盖 U |

合起来是 U ⊆ R ⊆ X。若第二个输入也为 &'a str，则传参时再产生 Y 覆盖 R 的约束。来源/目标是根据当前检查边界确定的；形参在调用边界是接收方，在函数体内又能作为返回表达式的来源。

调用处推断 R 必须同时满足所有约束；函数体中的通用 'a 则不能随便挑一个便利范围，它必须在声明契约下正确。这两个检查视角要分开。

### 8.3 创建借用与结构体字段

创建对数据的借用时，被借用数据必须在借用需要有效的范围内保持有效。构造 `Excerpt<'a> { text: ... }` 时，字段需要 &'a str，初始化表达式提供一个引用，其有效性保证必须覆盖这个要求；之后通过字段读取，又让 a 必须覆盖这些读取的需要。

因此结构体和函数不是两套相反规则，都是“来源保证覆盖接收处要求，再覆盖实际使用需求”。但不能把结构体实例的整个词法作用域直接当成 a，仍需根据实际类型及借用使用分析。

### 8.4 显式约束与参数作用域

`'a: 'b` 直接指定 a 覆盖 b，允许相等。impl、函数或结构体各自声明的 'a 仅在各自参数作用域内有意义；两个不相干函数都写 'a，不表示它们自动关联。

### 8.5 适用边界

上述“较长共享引用满足较短共享引用要求”的方向对应 &'a T 在 a 上的协变。嵌套泛型、可变引用内部的类型参数、函数指针等还需要按类型的变型规则分析，不能把同一方向机械套到任意出现 'a 的地方。本节不展开完整变型课程。

来源：[Rust Reference：子类型与变型](https://doc.rust-lang.org/reference/subtyping.html)、[生命周期约束](https://doc.rust-lang.org/reference/trait-bounds.html)、[Region inference](https://rustc-dev-guide.rust-lang.org/borrow-check/region-inference.html)。核查日期：2026-10-20。

## 9. 如何识别借用来源与使用

先澄清术语：'a 是有效性参数，不是一个带有唯一来源地址的引用。代码里应追踪具体引用的产生与流动，再由类型和签名得出约束。上节的“来源”主要指当前类型检查中提供引用的表达式；它不一定就是最初拥有数据的变量。

```rust
fn relay<'a>(x: &'a str, note: &str) -> &'a str {
    println!("{note}");
    x
}

fn main() {
    let owner = String::from("rust");
    let input = owner.as_str();
    let output;
    {
        let note = String::from("备注");
        output = relay(input, note.as_str());
    }
    println!("{output}");
}
```

### 9.1 先找数据，再找借用产生处

owner 拥有字符串数据；owner.as_str() 从已有数据产生共享借用。没有显式 & 并不表示没借用：方法可能通过 &self 借用接收者并返回引用。最直接的创建形式是 &value / &mut value；as_str、切片、迭代器等需要查看类型或方法签名，而不是凭函数名猜。

`let input = ...` 的绑定保存引用，不拥有字符串数据。复制、赋值、存入字段和从函数返回，都可能让已有引用继续流动，并不意味着产生了独立的数据副本或新的所有者。

### 9.2 按每个检查位置区分提供与要求

| 代码位置 | 当前角色 |
| --- | --- |
| owner.as_str() | 借用 owner 的字符串数据，为 input 提供引用 |
| relay(input, ...) | input 在此被用作实参；它提供的保证必须满足形参 x 的要求 |
| 函数体尾表达式 x | x 被用作返回表达式，为输出类型提供引用 |
| output = relay(...) | 保存返回引用，后续使用仍受签名声明的关系约束 |
| println!("{output}") | 读取引用所指内容，需要底层数据此时仍有效 |

“来源”和“使用”不是把变量永久分成两类。同一个 input，在相对 owner.as_str() 时是接收者，在相对形参 x 时又是提供者；尾表达式 x 既使用输入引用，也为返回值提供引用。

### 9.3 使用不只是打印

解引用读取、通过引用写入、调用方法、作为实参传递、返回、存入另一个仍需使用的容器等，都可能产生或传播借用有效性要求。要关注能否通过引用访问数据，以及借用/移动规则，不要只数 println。

数据流视角帮助理解；编译器不是仅按变量名逐行扫描，还要分析控制流、移动和类型约束。值的类型及析构行为也可能影响有效性要求，不把“最后一个显式打印位置”当作所有代码的通用算法。

### 9.4 哪些引用与同一个参数关联，要看声明

在 relay 的签名中，x 和输出显式共享 'a；note 是另一个省略了名字的输入生命周期。即使 relay 内部确实使用了 note，也不会因此把 note 自动关联到输出的 'a。

若将 note 也标为 &'a str，调用边界就要求 note 的引用也支持同一个参数。函数体可能只返回 x，但调用者仍不能去掉签名中的这个要求。

因此要分开两个问题：

1. 哪个表达式实际借用/提供了数据？沿表达式、赋值与方法实现追踪。
2. 哪些有效性要求被契约关联起来？看类型、函数签名、省略规则及显式 bounds。

读函数实现可以理解具体数据来源，但检查调用能否成立时，必须遵守签名中的全部约束。

依据：[MIR 借用检查](https://rustc-dev-guide.rust-lang.org/borrow-check.html)、[Region inference](https://rustc-dev-guide.rust-lang.org/borrow-check/region-inference.html)。本节 relay 是对已验证 E02 补全版的重命名教学示例，未另外声明为单独编译的新实验。
