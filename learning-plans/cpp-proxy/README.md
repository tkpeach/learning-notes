[专题目录](../README.md) · [仓库首页](../../README.md)

## 版本策略

微软仓库已归档，后续开发移至 `ngcpp/proxy`。本专题统一使用 **4.1.0**，提交 `1c7ca609aba6d73df06183c14db9d2d210399af3`。历史文章中的 API 需与此版本核对。当前维护、采用情况和标准化状态见[核查记录](resources.md#现状快照2026-10-20)。

依赖 C++20；示例刻意不依赖 `std::format`，避免把格式化库支持问题混进多态学习。完整复现命令在[示例说明](examples/README.md)。第三方源码及构建产物放临时目录，不纳入笔记仓库。

## 四章路线

建议共 4–6 小时，含阅读和动手；时间是预算，不是已发生的学习耗时。只想先入门时，用 45–60 分钟完成第一章并读第二章的所有权表。

### 第一章：它改变了什么（45–60 分钟）

阅读讲义 M01–M02 和 `01-basic.cpp`。重点是：具体对象没有共同基类，但调用方仍可使用一个固定类型的运行时接口。

- A1：先不执行，预测两条链路的输出，分别标出接口定义、构造边界、调用位置。运行后解释为什么 `area_of` 不需要模板。
- A2：增加一个 `Triangle`，保持调用方 `area_of` 不变。输入底 6、高 4，新增面积应为 12。用编译及总面积断言验证；这只验证可扩展性，不验证性能。

可在新会话独立使用：

```text
请教我 C++ Proxy 第一章。背景：有 C++ 基础，了解 virtual、模板、unique_ptr，但没用过 Proxy。
以本专题固定的 ngcpp/proxy 4.1.0 为准；先读取 learning-plans/cpp-proxy/README.md、lesson.md、resources.md 和 examples/01-basic.cpp。
完整讲解静态多态、虚函数和非侵入式运行时多态的区别，补齐 facade、dispatch、convention、proxy 四个术语；用现有完整示例对照构造与调用链。
然后一起布置 A1、A2，让我先预测和修改再反馈。不要提前把验收答案当作我的回答。
将真实判断、代码修改、反馈和实际验证更新到 learning-log.md；材料准备与学习者掌握分开记录。
```

### 第二章：所有权与表达式（60–90 分钟）

阅读讲义 M03–M04、`02-ownership.cpp` 和 `03-expressions.cpp`。

- B1：输入一个可修改 `Cell`。对裸指针、`shared_ptr`、`make_proxy` 三种构造先预测“复制后修改是否影响原对象”，再用示例断言验证。解释复制的是哪一种 P；不要只背深浅复制结论。
- B2：为第三方 `Reading` 增加自由函数能力；解释 `p->describe()` 和 `p.use_count()` 的操作对象。运行现有示例，再把支持 `use_count` 的 P 改为 `unique_ptr`，保存为失败副本，观察能力检查；不要覆盖正常版本。

```text
请教我 C++ Proxy 第二章。背景：知道 Proxy 用 facade 描述运行时接口，需要深入理解生命周期。
读取 learning-plans/cpp-proxy/lesson.md 的 M03–M04、examples/02-ownership.cpp、03-expressions.cpp 与 learning-log.md。使用固定的 4.1.0，提供完整起始代码，不依赖上一章练习产物。
先完整解释 P 与 *P、拥有与借用、copyability、make_proxy 的值复制、direct/indirect convention 和 ADL，再布置 B1、B2 一组练习。
等我提交预测或代码后集中反馈。保留失败副本，记录理论预期和实际诊断，不能把我尚未完成的项目写成已掌握。
```

### 第三章：沿着调用走进源码（90–120 分钟）

阅读[实现原理](implementation.md)和 `04-erasure-model.cpp`，在固定提交中按符号搜索。

- C1：对输入 `Rectangle{3,4}`，在纸上画出模型的 `T → const void* + 函数地址 → 具体 T`，再编译执行。增加 `perimeter` 能力需要改哪些地方？先给设计，不急着实现完整库。
- C2：为官方链路 `make_proxy → initialize<P> → accessor → invoke_impl → reinterpret_invoke → MemArea` 标注每一步发生在编译期还是运行期，指出真正擦除类型和恢复 P 的位置。用固定源码核对，不以教学模型替代真实路径。

```text
请教我 C++ Proxy 第三章。背景：能写基本 facade 和 proxy，需要理解模板如何生成运行时分派。
读取 learning-plans/cpp-proxy/implementation.md、examples/04-erasure-model.cpp 和 learning-log.md；官方源码以 4.1.0 提交 1c7ca609aba6d73df06183c14db9d2d210399af3 为准。
先给完整的一能力类型擦除模型，解释 void*、函数指针、模板实例化、存储与生命周期；随后沿官方源码符号跟踪 make_proxy 和 area 调用，区分模型省略的能力。
布置 C1、C2，要求我标注编译期/运行期并讲解调用链后再反馈。源码尚未取得时如实标为未核查，不猜测行号或实验结果。将过程固化到日志。
```

### 第四章：约束、性能与是否采用（45–90 分钟）

阅读讲义 M05–M06、现状证据和 `05-constraints-fail.cpp`。

- D1：分别编译 CASE 1–4，记录错误阶段、缺失的能力和最小修复；保留原失败代码。预期四次失败，错误原因应不同；编译失败本身不算验证完成，需核对诊断。
- D2：选择一个真实接口，用半页写“现有主路径、引入目标、候选方案、所有权约定、验证计划、放弃条件”。若做性能实验，先保持对象分配、访问顺序和业务工作量一致。验收是能解释选择及代价，不要求结论一定采用 Proxy。

```text
请教我 C++ Proxy 第四章。背景：已经了解基本接口和类型擦除，需要判断工程适用性。
读取 learning-plans/cpp-proxy/lesson.md 的 M05–M06、resources.md、examples/05-constraints-fail.cpp 和 learning-log.md。固定使用 4.1.0，先解释约束错误、借用风险、编译和二进制成本、基准公平性，再一起布置 D1、D2。
对四个 CASE 逐一记录实际错误与原因；没有执行就不能说已验证。评估真实接口时，以已知正常行为链路为基线，保留 virtual/模板/variant 等候选，不能为了演示绕过主路径。
收到我的分析后集中反馈，更新过程与复习卡；仅把实际讨论形成的稳定结论写入 topics 或每日日志。
```

## 学习与复习约定

每轮提供一个完整模块（直觉、机制、语法、对照示例、边界），再一起练习和反馈，避免一句话讲解配一个小问题反复等待。日志只保存有价值的原始判断和纠正，不抄整段聊天。

完成一章后当天用复习卡闭卷讲一次；隔 1 天重做错题，隔 1 周换一个类型迁移，隔 1 月重新评估接口选择。这是复习建议，不创建自动提醒。
