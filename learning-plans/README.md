# 学习专题计划

存放可以在新会话中独立开始的系统学习路线、教学提示词和练习。

## 与现有目录的关系

| 目录 | 用途 |
| --- | --- |
| `../2026/` 等年份目录 | 按月记录日常学习结论 |
| `../topics/` | 将已学知识整理成主题笔记 |
| `learning-plans/<topic>/` | 按阶段、章节组织主动学习计划与练习 |

学习计划不是完成记录。完成某章后，可以在年月日志记录结论，并将稳定知识整理到 `topics/`，通过链接关联，不必复制整份计划。

## 组织约定

每个专题使用一个小写英文、连字符分隔的稳定目录名，例如 `mlir/`、`cpp-concurrency/`。专题的 `README.md` 是完整学习计划的唯一正文入口。

```text
learning-plans/
├── README.md                  # 专题索引与组织约定
├── mlir/
│   └── README.md              # 完整路线、阶段/章节提示词、练习与验证方法
└── <another-topic>/           # 有实际内容时再创建
    └── README.md
```

专题内后续确有产出时，可增加 `exercises/01-<name>/` 保存代码与输入，或增加 `resources.md` 保存扩展资料；当前不创建空目录，也不预填学习完成状态。不要同时维护内容相同的总计划和逐章副本。

每个专题正文应包含：

1. 目标、适用基础、阶段安排和建议投入。
2. 必要工具、版本策略、资料来源和验证范围。
3. 每个阶段与每章可独立复制的提示词。提示词自身包含必要背景、主题、完整起始材料要求和验收标准，不要求读取其他章节或使用其输出。
4. 每章 1—2 道明确的练习，注明输入、任务、预期观察、验证途径和限制。
5. 网站与工具的核查状态。区分解析验证、变换检查、真实执行和性能测试，不把未执行实验标为已通过。

新增专题时，同时更新本目录索引与[仓库首页](../README.md)的 Learning Plans 导航。章节内部使用稳定锚点，方便笔记引用。
